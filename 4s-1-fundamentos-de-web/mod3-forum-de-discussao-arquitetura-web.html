Materiais

A Arquitetura WEB é uma especialização de arquitetura de software que abrange os aspectos típicos e característicos da WEB. Como visto no módulo 1, a WEB é um serviço distribuído, ancorado em diversas camadas de protocolos de redes, a arquitetura Cliente/Servidor foi a que mais influenciou e deu base para outras arquiteturas.

Conteúdo

Realize buscas na web utilizando combinações das palavras-chave “arquitetura”, “web”, “software” com outras que julgar de interesse a este fórum. Analise os resultados, escolha um subtipo de arquitetura, apresente-o no tópico e discuta suas características, uso típico, vantagens e desvantagens.

Resolução

Apresentação da Arquitetura REST (Representational State Transfer).

Características:

A arquitetura REST utiliza HTTP como protocolo de comunicação, e os recursos são acessados por meio de URL's, representados em formatos como JSON ou XML.

Segue princípios como:

  1. Cliente-Server:
    • Separação clara entre cliente e servidor, promovendo independência entre as partes.
  2. Stateless:
    • Cada requisição do cliente ao servidor deve conter todas as informações necessárias para ser compreendida e processada, sem depender de requisições anteriores.
  3. Cacheable:
    • As respostas podem ser armazenadas em cache para melhorar a eficiência.
  4. Uniform Interface:
    • Utiliza operações padrão do protocolo HTTP, como GET, POST, PUT, DELETE.
Uso:

A arquitetura REST é amplamente utilizada em APIs web devido à sua simplicidade e à integração fácil com diversos sistemas. É usada em aplicações móveis, sistemas de microsserviços e em APIs públicas para serviços como redes sociais e mapas.

Vantagens:
  1. Escalabilidade:
    • Por ser Stateless(recursos isolados), a arquitetura REST permite maior escalabilidade.
  2. Flexibilidade:
    • Funciona com qualquer linguagem de programação que suporte HTTP.
  3. Cache:
    • Aproveita o cacheamento para otimizar a performance.
Desvantagens:
  1. Limitações em operações complexas:
    • Para operações que vão além do CRUD, REST pode se tornar mais complexo.
  2. Overhead em requisições:
    • O uso de HTTP pode adicionar overhead em comparação a outros protocolos.
