Pergunta 1

Em Android, um Toast…

  • a. Exibe uma mensagem na central de notificações.
  • b. Exibe a mensagem em uma caixa de diálogo separada.
  • c. Exibe a mensagem na Activity e desaparece automaticamente após um tempo.
  • d. Exibe a mensagem na Activity e reaparece recorrentemente.
  • e. Exibe a mensagem na Activity e não desaparece automaticamente.
Resposta: c. ✅

📌 Explicação:

  • Um Toast no Android é um pequeno aviso que:
    • Aparece na parte inferior da tela por padrão (dentro da Activity atual)
    • Some automaticamente após um curto período (2-3 segundos)
    • Não requer interação do usuário
    • É implementado com uma única linha de código:
Toast.makeText(context, "Mensagem", Toast.LENGTH_SHORT).show();

Pergunta 2

Assinale a linha de código correta que está preparando um aplicativo para interagir com os sensores do dispositivo Android, chamando o serviço de sistema.

  • a. sensorChannel = (SensorChannel) getSystemService(SENSOR_SERVICE);.
  • b. sensor = (Sensor) getSystemService(SENSOR_SERVICE);.
  • c. sensorManager = (SensorManager) getSystemService(SENSOR_SERVICE);.
  • d. sensorEventListener = (SensorEventListener) getSystemService(SENSOR_SERVICE);.
  • e. sensorEvent = (SensorEvent) getSystemService(SENSOR_SERVICE);.
Resposta: c. ✅

📌 Explicação:

  • Em Android, o acesso aos sensores é feito através do SensorManager, que é um serviço do sistema.
  • O método getSystemService() retorna uma instância do SensorManager quando passamos a constante SENSOR_SERVICE.
  • A conversão ((SensorManager)) é necessária porque getSystemService() retorna um Object.

Exemplo:

                public class SensorActivity extends Activity implements SensorEventListener {
                    private SensorManager sensorManager;
                    private Sensor accelerometer;
                
                    @Override
                    protected void onCreate(Bundle savedInstanceState) {
                        super.onCreate(savedInstanceState);
                        setContentView(R.layout.activity_main);
                        
                        // Linha correta para obter o serviço
                        sensorManager = (SensorManager) getSystemService(SENSOR_SERVICE);
                        
                        // Obter sensor específico
                        accelerometer = sensorManager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
                    }
                
                    @Override
                    protected void onResume() {
                        super.onResume();
                        // Registrar listener
                        sensorManager.registerListener(this, accelerometer, SensorManager.SENSOR_DELAY_NORMAL);
                    }
                }

Pergunta 3

Assinale a alternativa que NÃO contém um sensor comumente presente em smartphones:

  • a. Sensor de temperatura.
  • b. Sensor de umidade.
  • c. Sensor de proximidade.
  • d. Sensor de luminosidade.
  • e. Nenhuma das alternativas.
Resposta: a. ❌

📌 Explicação:

  • Embora existam sensores de temperatura em alguns smartphones, não são comuns na maioria dos dispositivos de consumo. Quando presentes, geralmente medem a temperatura interna da bateria/CPU, não a ambiente.

Exemplo:

                SensorManager manager = (SensorManager) getSystemService(SENSOR_SERVICE);
                // Verifica se o sensor de temperatura existe
                boolean hasTempSensor = manager.getDefaultSensor(Sensor.TYPE_AMBIENT_TEMPERATURE) != null;
                Toast.makeText(this, "Tem sensor de temperatura? " + hasTempSensor, Toast.LENGTH_SHORT).show();

Pergunta 4

Objeto responsável por encapsular as informações de um evento ocasionado por um sensor:

  • a. ManagerSensor.
  • b. EventSensor.
  • c. Sensor.
  • d. SensorEvent.
  • e. SensorManager.
Resposta: d. ✅

📌 Explicação:

  • O que é SensorEvent?
    • Classe do Android que contém os dados brutos do sensor quando ocorre uma mudança
    • Armazena:
      • Valores do sensor (values[])
      • Tipo de sensor (sensor)
      • Precisão (accuracy)
      • Timestamp (timestamp)

Exemplo:

                @Override
                public void onSensorChanged(SensorEvent event) {
                    // event é uma instância de SensorEvent
                    float x = event.values[0]; // Dados do sensor
                    int type = event.sensor.getType(); // Tipo (ex: ACCELEROMETER)
                }

Pergunta 5

Métodos abstratos que precisam ser sobrescritos ao implementar a interface SensorEventListener na classe.

  • a. onUpdated() e onAccuracyChanged().
  • b. onSensorChanged() e onAccuracyChanged().
  • c. onDeleted() e onAccuracyChanged().
  • d. onSensorChanged() e onUpdated().
  • e. onSensorChanged() e onCreated().
Resposta: b. ✅

📌 Explicação:

  • Ao implementar a interface SensorEventListener no Android, você deve sobrescrever estes dois métodos:
    • onSensorChanged(SensorEvent event)
      • Chamado quando os valores do sensor mudam
      • Fornece os dados atualizados via objeto SensorEvent
    • Exemplo:
      •                         @Override
                        public void onSensorChanged(SensorEvent event) {
                            float x = event.values[0]; // Valor do eixo X (para acelerômetro)
                        }
    • onAccuracyChanged(Sensor sensor, int accuracy)
      • Chamado quando a precisão do sensor muda
      • Níveis comuns: SENSOR_STATUS_ACCURACY_LOW, SENSOR_STATUS_ACCURACY_MEDIUM, etc.
    • Exemplo:
      •                         @Override
                        public void onAccuracyChanged(Sensor sensor, int accuracy) {
                            if (accuracy == SensorManager.SENSOR_STATUS_UNRELIABLE) {
                                Log.w("Sensor", "Dados não confiáveis");
                            }
                        }

Pergunta 6

Método responsável por obter o sensor padrão para um determinado tipo:

  • a. getSensor().
  • b. getDefaultSensor().
  • c. getSystemService().
  • d. getSystemSensor().
  • e. getSensorEvent().
Resposta: b. ✅

📌 Explicação:

  • O método getDefaultSensor() pertence à classe SensorManager e é usado para obter o sensor padrão de um tipo específico. Aqui está como ele funciona:
  • Sintaxe:
    • Sensor sensor = sensorManager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
  • Parâmetros:
    • Recebe uma constante que representa o tipo de sensor (ex: Sensor.TYPE_ACCELEROMETER, Sensor.TYPE_LIGHT)
  • Retorno:
    • Retorna uma instância de Sensor correspondente ao tipo solicitado
    • Retorna null se o sensor não estiver disponível no dispositivo

Exemplo completo:

                SensorManager sensorManager = (SensorManager) getSystemService(SENSOR_SERVICE);
                Sensor lightSensor = sensorManager.getDefaultSensor(Sensor.TYPE_LIGHT);

                if (lightSensor != null) {
                    // Sensor disponível, pode registrar o listener
                    sensorManager.registerListener(this, lightSensor, SensorManager.SENSOR_DELAY_NORMAL);
                } else {
                    // Sensor não disponível neste dispositivo
                    Toast.makeText(this, "Sensor de luminosidade não disponível", Toast.LENGTH_SHORT).show();
                }

Pergunta 8

Tipos de dados suportados pelo SQLite:

  • a. Integer.
  • b. Real.
  • c. Text.
  • d. Blob.
  • e. Todas as alternativas estão corretas.
Resposta: e. ✅

📌 Explicação:

  • O SQLite suporta os seguintes tipos de dados nativos (conhecidos como "storage classes"), conforme documentação oficial:
    • Números inteiros com sinal (1, 2, 3, 4, 6 ou 8 bytes)
    • Números de ponto flutuante (8-byte IEEE)
    • Strings de caracteres (codificação UTF-8, UTF-16BE ou UTF-16LE)
    • Dados binários (armazenados exatamente como inseridos)

Pergunta 9

Acelerômetro, Giroscópio e Magnetômetro são tipos de sensores de movimento presentes nos smartphones cujos eventos podem ser tratados nos aplicativos.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • Os três sensores mencionados (Acelerômetro, Giroscópio e Magnetômetro) são de fato sensores de movimento comumente presentes em smartphones Android e iOS, e seus eventos podem ser tratados em aplicativos.
    • Acelerômetro
      • Mede a aceleração linear (incluindo a gravidade) nos eixos X, Y e Z.
    • Giroscópio
      • Mede a velocidade angular (rotação) nos eixos X, Y e Z.
    • Magnetômetro (Sensor de Campo Magnético)
      • Detecta o campo magnético da Terra (bússola).

Pergunta 10

Classe que oferece vários métodos para acessar e listar sensores, registrar e cancelar o registro de listeners de eventos do sensor e coletar informações de orientação.

  • a. Sensor.
  • b. SensorManager.
  • c. SensorEvent.
  • d. SensorEventListener.
  • e. SensorChannel.
Resposta: b. ✅

📌 Explicação:

  • A classe SensorManager é o componente central do Android para interação com sensores. Ela fornece:
    • Acesso aos sensores disponíveis:
      • List <Sensor> sensors = sensorManager.getSensorList(Sensor.TYPE_ALL);
    • Registro de listeners:
      • sensorManager.registerListener(listener, sensor, rate);
    • Cancelamento de listeners:
      • sensorManager.unregisterListener(listener);
    • Obtenção do sensor padrão:
      • Sensor accelerometer = sensorManager.getDefaultSensor(Sensor.TYPE_ACCELEROMETER);
    • Métodos de orientação (depreciados, mas ainda relevantes):
      •                         float[] rotationMatrix = new float[9];
                        sensorManager.getRotationMatrix(rotationMatrix, null, accelerometerData, magnetometerData);
