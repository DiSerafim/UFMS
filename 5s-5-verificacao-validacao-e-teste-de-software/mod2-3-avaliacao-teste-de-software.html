Pergunta 2

Marque a afirmação correta a respeito da introdução de defeitos no processo de desenvolvimento de um software.

  • a. São gerados na comunicação entre a equipe de desenvolvimento.
  • b. É resultado da tradução incorreta de informações.
  • c. Quanto antes a presença do defeito for revelada, menor o curso de correção.
  • d. Todas as afirmações estão corretas.
Resposta: d. ✅
  • Erros de entendimento entre analistas, desenvolvedores e testadores geram defeitos.
  • Falhas na interpretação de requisitos e na documentação também causam defeitos.
  • Defeitos detectados no início custam menos para serem corrigidos do que os encontrados nas fases finais.

Pergunta 4

No Teste de Software, o critério de análise do valor limite que avalia o comportamento do software indicando entradas com valores próximos aos limites especificados, valor máximo e mínimo, por exemplo, é utilizado em qual técnica de teste?

  • a. Caixa Branca.
  • b. Caixa Cinza.
  • c. Caixa Preta.
  • d. Nenhuma das técnicas mencionadas.
Resposta: c. ✅

📌 Explicação:

  • O critério de Análise de Valores Limite (Boundary Value Analysis) é uma técnica de teste de Caixa Preta.
  • Na Caixa Preta, o foco é testar as funcionalidades do sistema conforme os requisitos, sem conhecimento da implementação interna.
  • Avalia-se especialmente os limites das entradas e saídas, como valores máximos e mínimos permitidos, buscando falhas comuns nessas fronteiras.

Pergunta 5

Os elementos que compõem a descrição de um Caso de Uso e que podem influenciar no projeto de Casos de Teste são: quem interage com o sistema (ator), o fluxo dos eventos ou ações e as pré e pós-condições.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • Os Casos de Uso descrevem como os usuários (atores) interagem com o sistema e são fundamentais para o desenvolvimento de Casos de Teste, pois fornecem:
    • Atores: Quem interage com o sistema;
    • Fluxo de eventos: As ações realizadas durante a interação;
    • Pré-condições: O que deve ser verdadeiro antes da execução do caso de uso;
    • Pós-condições: O que deve ser garantido após a execução.

Pergunta 6

Selecione a alternativa que não compõem as etapas de Teste de Software.

  • a. Levantamento de Requisitos.
  • b. Análise dos Resultados.
  • c. Execução.
  • d. Projeto de Casos de Teste.
Resposta: a. ✅

📌 Explicação:

  • O Levantamento de Requisitos faz parte da fase de Análise de Requisitos no processo de desenvolvimento de software, não é uma etapa específica do Teste de Software.

Pergunta 7

Selecione o teste no qual os requisitos de teste são derivados a partir dos defeitos frequentemente cometidos durante o processo de desenvolvimento.

  • a. Teste Baseado em Defeitos.
  • b. Teste Aleatório.
  • c. Teste Estrutural.
  • d. Teste Funcional.
Resposta: a. ✅

📌 Explicação:

  • Teste Baseado em Defeitos: Tem como objetivo identificar falhas comuns que costumam ocorrer durante o desenvolvimento. Os requisitos de teste são criados com base no histórico de erros, defeitos típicos e falhas frequentes encontradas em projetos anteriores ou na prática da equipe.

Pergunta 8

No contexto do Teste de Software, os Casos de Uso podem apoiar o entendimento dos requisitos funcionais.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • Os Casos de Uso são uma técnica amplamente utilizada para descrever os requisitos funcionais de um sistema. Eles representam interações entre o usuário (ator) e o sistema, mostrando os fluxos de ações necessários para alcançar um determinado objetivo.
    • Na prática do Teste de Software, os Casos de Uso ajudam a:
    • Entender o comportamento esperado do sistema;
    • Identificar cenários de teste baseados nos fluxos normais e alternativos;
    • Garantir que os requisitos funcionais sejam cobertos pelos testes.

Pergunta 9

No Teste de Software, o particionamento de equivalência tem por objetivo reduzir o número de casos de teste, separando as entradas em válidas e inválidas.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • O Particionamento de Equivalência é uma técnica de teste de software do tipo Caixa Preta, cujo objetivo é reduzir o número de casos de teste, sem comprometer a cobertura dos cenários importantes.
  • ➡️ Essa técnica consiste em dividir as entradas possíveis em classes de equivalência, onde se assume que testar um valor de cada classe é suficiente para representar o comportamento de todos os outros valores dessa classe.
  • As classes são normalmente divididas em:
    • Entradas válidas: valores que o sistema deve aceitar.
    • Entradas inválidas: valores que o sistema deve rejeitar ou tratar com erro.

Pergunta 10

O estilo normalmente adotado para o registro do conteúdo de um Caso de Uso é o chamado cenário principal de sucesso. Dessa forma, não é necessário considerar os fluxos alternativos ou exceções no projeto de Casos de Teste.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Falso. ✅

📌 Explicação:

  • Embora o cenário principal de sucesso (ou fluxo principal) seja o caminho mais comum e desejado de execução de um Caso de Uso, os fluxos alternativos e as exceções também são fundamentais no projeto de Casos de Teste.
  • Testar apenas o fluxo principal não garante a cobertura completa dos comportamentos esperados do sistema. É importante testar também:
    • Fluxos alternativos: variações válidas do comportamento principal.
    • Fluxos de exceção: situações anormais ou erros que o sistema deve tratar adequadamente.
  • Exemplo:
    • Fluxo principal: Login bem-sucedido.
    • Fluxo alternativo: Usuário esqueceu a senha e usa o recurso “Esqueci minha senha”.
    • Fluxo de exceção: Usuário digita senha incorreta três vezes e a conta é bloqueada.
