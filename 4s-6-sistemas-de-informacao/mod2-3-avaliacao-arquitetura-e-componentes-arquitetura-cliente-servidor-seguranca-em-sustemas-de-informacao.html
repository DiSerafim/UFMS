Questionário ✅ ❌

Pergunta 1

Em termos de arquitetura de software, o que é "Encapsulamento"?

  • a. Agrupar todos os componentes em um único módulo.
  • b. Centralizar todas as decisões de design em um único ponto.
  • c. Proteger a implementação interna dos módulos, expondo apenas interfaces necessárias.
  • d. Expor todas as implementações internas para facilitar a manutenção.
Resposta: C. ✅

Resolução:

  • Encapsulamento é um princípio fundamental em arquitetura e design de software, associado à ocultação dos detalhes internos de um módulo ou componente e à exposição apenas das interfaces essenciais. Isso facilita a manutenção, melhora a modularidade e reduz o acoplamento entre os componentes do sistema. Ele é amplamente utilizado para:
    • Proteger dados e funcionalidades: Os detalhes de implementação ficam inacessíveis a outras partes do sistema.
    • Promover modularidade: Cada módulo se torna mais independente.
    • Reduzir erros e impactos: Mudanças internas em um módulo não afetam outros, desde que a interface pública permaneça a mesma.

Pergunta 2

O que representa o modelo cliente-servidor na arquitetura de software?

  • a. Uma clara separação entre as responsabilidades do cliente e do servidor.
  • b. Um conjunto de protocolos de comunicação.
  • c. Uma linguagem de programação específica.
  • d. Um sistema distribuído.
Resposta: A. ✅

Resolução:

  • O modelo cliente-servidor na arquitetura de software é uma estrutura que organiza aplicações em dois papéis principais:
    • Cliente: É responsável por fazer solicitações ao servidor. Geralmente, representa a interface que o usuário utiliza, como um navegador web ou aplicativo.
    • Servidor: É responsável por processar as solicitações recebidas dos clientes, realizar as operações necessárias (como acessar um banco de dados ou processar dados) e retornar os resultados ao cliente.

Pergunta 3

O que define a arquitetura de sistemas de informação?

  • a. O sistema operacional utilizado.
  • b. As interfaces do usuário.
  • c. A estrutura de dados utilizada.
  • d. A estrutura organizacional e o design dos componentes.
Resposta: D. ✅

Resolução:

  • A arquitetura de sistemas de informação refere-se ao design estruturado que define como os componentes de um sistema de informação (como hardware, software, dados, processos e interfaces de usuário) são organizados e interagem para suportar as operações e os objetivos de uma organização.
  • Ela engloba aspectos como:
    • A estrutura organizacional do sistema, detalhando como diferentes componentes trabalham juntos.
    • O design lógico e físico, que inclui a configuração de servidores, bancos de dados e clientes.
    • Os fluxos de dados e processos de negócio que o sistema deve gerenciar.

Pergunta 4

A arquitetura de sistemas de (.....) considera a organização dos (.....) como parte integrante da sua (.....).

Opções: informação, dados, definição.

Resposta: Verdadeiro. ✅

Resolução:

  • A arquitetura de sistemas de informação considera a organização dos dados como parte integrante da sua definição.
    • A arquitetura de sistemas de informação considera a organização dos dados como parte integrante de sua definição, pois os dados são elementos fundamentais no funcionamento de qualquer sistema de informação. Essa organização envolve a estruturação lógica e física dos dados, permitindo que sejam armazenados, acessados e processados de forma eficiente para atender às necessidades da organização.
    • Componentes relacionados à organização de dados:
      • Modelagem de Dados: Definição de como os dados serão estruturados e relacionados (por exemplo, usando diagramas entidade-relacionamento).
      • Banco de Dados: Sistemas utilizados para armazenar, organizar e acessar os dados (como SQL, NoSQL).
      • Fluxo de Dados: Como os dados se movem entre os componentes do sistema.
      • Integração e Governança: Garantir consistência, segurança e conformidade ao manipular dados.

Pergunta 5

A arquitetura de sistemas de informação organiza processos, dados, tecnologias e interfaces para atender aos objetivos organizacionais.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

Resolução:

  • A arquitetura de sistemas de informação organiza processos, dados, tecnologias e interfaces com o objetivo de alinhar o funcionamento do sistema às necessidades e objetivos organizacionais. Essa abordagem garante que os recursos sejam utilizados de forma integrada e eficiente, atendendo às demandas operacionais e estratégicas da organização.
  • Essa organização engloba:
    • Processos: Estruturação de atividades para alcançar eficiência e qualidade.
    • Dados: Gerenciamento e integração de informações cruciais.
    • Tecnologias: Seleção e implementação de ferramentas adequadas.
    • Interfaces: Design de interações para melhorar a usabilidade e funcionalidade.

Pergunta 6

A separação de preocupações (Separation of Concerns) visa dividir o sistema em partes que se concentram em preocupações específicas.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

Resolução:

  • A separação de preocupações (Separation of Concerns, SoC) é um princípio fundamental no design e arquitetura de sistemas. Ele propõe dividir o sistema em partes (ou módulos) que tratam de aspectos específicos ou preocupações distintas. Isso facilita a manutenção, a evolução do sistema e o entendimento do código, além de permitir que diferentes partes sejam desenvolvidas, testadas e modificadas de forma independente.
  • Por exemplo:
    • Camadas em um sistema: Interface do usuário, lógica de negócios e acesso a dados podem ser separadas.
    • Arquitetura modular: Cada módulo trata de uma funcionalidade específica, como autenticação, processamento de dados ou relatórios.

Pergunta 7

Qual é a definição de "Separação de Preocupações" (Separation of Concerns) no contexto de design arquitetural?

  • a. Centralizar todas as decisões de design em um único ponto.
  • b. Agrupar todas as preocupações em um único módulo.
  • c. Ignorar completamente as preocupações do sistema.
  • d. Dividir o sistema em partes que se concentram em preocupações específicas.
Resposta: D. ✅

Resolução:

  • A separação de preocupações (Separation of Concerns, SoC) é um princípio fundamental no design arquitetural de sistemas, que consiste em organizar o sistema em partes independentes, cada uma focada em um aspecto específico ou funcionalidade. Essa abordagem visa melhorar a modularidade, a manutenibilidade e a escalabilidade do sistema, permitindo que alterações em uma parte não afetem diretamente as outras.
  • Por exemplo:
    • Interface do Usuário: Lidando com interações visuais.
    • Lógica de Negócios: Gerenciando regras de operação do sistema.
    • Banco de Dados: Armazenando e recuperando informações.

Pergunta 8

O nível de abstração de arquitetura "Nível do Modelo" se concentra na produção do modelo de design para configurações específicas.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ❌

Resolução:

  • O "Nível do Modelo" na abstração de arquitetura de sistemas refere-se ao foco na criação de modelos de design detalhados e específicos para um conjunto particular de requisitos ou configurações. Nesse nível, o objetivo é gerar representações que orientem a implementação prática do sistema, considerando as características específicas do ambiente e da infraestrutura onde ele será implantado.
  • Por exemplo:

    • Criar um modelo que reflita a interação entre os elementos da arquitetura para atender às demandas específicas do projeto.

Pergunta 9

Alta coesão dentro dos (.....) significa que as (.....) relacionadas não estão (.....) entre diferentes módulos.

Opções: módulos, funcionalidades, distribuídas.

Resposta: Verdadeiro. ✅

Resolução:

  • Alta coesão dentro dos módulos significa que as funcionalidades relacionadas não estão distribuídas entre diferentes módulos.
    • Alta coesão refere-se a um princípio de design em que todas as funcionalidades ou responsabilidades de um módulo são relacionadas e focadas em uma única tarefa ou propósito. Isso implica que as funcionalidades relacionadas devem ser agrupadas dentro de um único módulo, em vez de estarem distribuídas entre diferentes módulos. Essa abordagem melhora a clareza, facilita a manutenção e reduz a complexidade do sistema, pois cada módulo trata de preocupações específicas e bem definidas.
    • Por exemplo:
      • Um módulo de "Gestão de Usuários" deve conter todas as funcionalidades relacionadas à criação, atualização e exclusão de usuários, em vez de espalhá-las por diferentes módulos.

Pergunta 10

No modelo cliente-servidor, a interação entre cliente e servidor ocorre principalmente por meio de requisições do servidor.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Falso. ✅

Resolução:

  • No modelo cliente-servidor, a interação entre o cliente e o servidor ocorre principalmente por meio de requisições do cliente, e não do servidor. O cliente envia requisições para o servidor, solicitando recursos ou serviços específicos, e o servidor processa essas requisições, retornando as respostas ao cliente. O servidor está geralmente à disposição para responder a qualquer requisição feita pelos clientes, mas é o cliente quem inicia a comunicação.
  • Exemplo:
    • Um navegador web (cliente) envia uma requisição para um servidor web para acessar uma página, e o servidor web responde com o conteúdo dessa página.
