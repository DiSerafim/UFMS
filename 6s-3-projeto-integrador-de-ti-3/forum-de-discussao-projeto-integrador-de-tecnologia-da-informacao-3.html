Olá, estudante!

Nesta disciplina, vamos tratar sobre o Projeto Integrador de Tecnologia da Informação III, com foco no desenvolvimento de ações de extensão e na construção de soluções web mais completas e confiáveis. Aqui, você vai aprofundar práticas de verificação, validação e testes (VVT), aplicar testes de software de forma estruturada, adotar boas práticas em serviços web (com atenção à segurança, documentação e versionamento) e avançar em integração e entrega contínuas, buscando qualidade do início ao fim do projeto. 🧪🔐🔁

Pense em um sistema que funciona, mas falha quando muda um detalhe, quando há muitos acessos ou quando alguém usa de um jeito diferente do esperado. Em projetos reais, qualidade não é enfeite, é confiança: revisar artefatos, testar cenários, documentar serviços e automatizar a entrega ajuda a evitar retrabalho e garante que a solução seja útil para quem precisa. ✅💻

Para este fórum, escolha uma solução web que você já está construindo ou conseguiria imaginar para uma demanda da comunidade e reflita como você garantiria qualidade: que partes você revisaria, que tipos de testes faria sentido aplicar, como documentaria e versionaria uma API e que automações simples colocaria na integração e entrega contínuas. 🔎📄⚙️

🌆 Cidade Virtual – Qualidade, testes e confiabilidade para conexão comunitária

Minha solução web de extensão é a Cidade Virtual, uma plataforma para conectar moradores, comércios locais e autônomos do bairro Cabanagem (Belém/PA). Com base nos aprendizados do Projeto Integrador III, organizei as seguintes práticas para garantir qualidade e confiabilidade desde o início.

🧪 1. VVT – Verificação, Validação e Testes

  • Verificação: Revisão por pares dos diagramas de caso de uso, DER (usuários, comércios, serviços, eventos, avaliações) e contratos da API.
  • Validação: Sessões com 3 comerciantes e 3 moradores para validar protótipo funcional no ambiente de homologação.
  • Testes unitários: Jest para validar regras de negócio (ex: cálculo de avaliação média, validação de perfis).
  • Testes de integração: Endpoints principais (cadastro, busca, criação de evento) com banco de dados real (PostgreSQL/MySQL).
  • Testes exploratórios manuais: Checklist de fluxos críticos (cadastro, login, busca, avaliação).

🔐 2. Boas práticas em serviços web

  • Segurança: Autenticação JWT com refresh token (perfis: morador, comerciante, admin), validação de entrada contra SQL Injection e XSS, HTTPS obrigatório, middleware de proteção de rotas.
  • Documentação: Swagger/OpenAPI automático (ex: /api/docs), README com exemplos de uso para a comunidade técnica.
  • Versionamento de API: URL versionada (/v1/comercios, /v2/eventos), Git Flow com branches main/develop/feature, changelog mantido no repositório.

⚙️ 3. Integração e Entrega Contínuas (CI/CD)

  • CI (GitHub Actions): Ao abrir PR ou push para develop → rodar linter (ESLint), testes unitários (Jest) e build da aplicação.
  • CD (Vercel + GitHub Actions): Merge na main → deploy automático em homologação (homolog.cidadevirtual.vercel.app). Criação de tag v*.*.* → deploy em produção com rollback simples.
  • Monitoramento simples: Logs estruturados e verificação de saúde da API (endpoint /health).

📊 Resumo da estratégia inicial (primeiro ciclo de qualidade)

✅ VVT: Testes unitários (Jest) + validação com usuários reais
✅ Testes: Integração + exploratório manual em homologação
✅ Segurança: JWT + validação + HTTPS
✅ Documentação: Swagger + README comunitário
✅ Versionamento: API /v1 e Git Flow simples
✅ CI/CD: GitHub Actions + Vercel (deploy automático)

🌱 Alinhamento com extensão e impacto social

A Cidade Virtual é uma tecnologia social que fortalece a economia local e a cidadania. Com essas práticas de qualidade, a plataforma sai do "funciona na minha máquina" para uma ferramenta confiável, que não quebra quando a comunidade começar a usar de verdade.
