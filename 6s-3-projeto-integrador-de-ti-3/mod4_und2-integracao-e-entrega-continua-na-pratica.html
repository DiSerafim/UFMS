🎯 Práticas de DevOps: do conceito à ação

Na unidade 1, vimos que DevOps é um conceito que visa unir Desenvolvimento (Dev) e Operação (Ops) com objetivo de agilizar a implantação de sistemas. CI (Continuous Integration) e CD (Continuous Delivery) são processos que permitem automação e monitoramento contínuo do ciclo de vida de aplicações.

warning Desafio comum:

Em times com desenvolvedores com pouca experiência, a implantação destas práticas pode ser mais desafiadora, mas traz muitos benefícios a médio e longo prazo. Nesta unidade, o objetivo principal é a apresentação e discussão de dicas e tecnologias que podem apoiar a implantação de CI/CD no projeto integrador desenvolvido.

🚀 Por onde começar? Pequenas automações

A chave para uma implantação bem-sucedida de CI/CD é começar pequeno e evoluir gradualmente. Não tente automatizar tudo de uma vez.

1
Identifique processos passíveis de automação
Mapeie atividades repetitivas que você faz manualmente (ex: rodar testes, verificar estilo de código, fazer deploy).
2
Verifique a viabilidade de automatizá-las
Existe ferramenta? O custo de automação compensa o ganho de tempo?
3
Busque ferramentas e alternativas
Pesquise soluções maduras, com boa documentação e comunidade ativa.
4
Automatize a atividade
Implemente a automação, teste e refine.

lightbulb Recomendação para projeto solo (Cidade Virtual)

Primeira automação sugerida: Conformidade de código (linter + formatador) rodando automaticamente antes de cada commit ou push.

📏 Exemplo prático: Conformidade de código

Conformidade de código refere-se ao processo de definir e aplicar padrões predefinidos de qualidade, estilo, boas práticas, etc., no desenvolvimento de artefatos de software. Esses padrões permitem melhorar a manutenção e facilitam a colaboração, garantindo um código padronizado.

☕ Java Checkstyle PMD SpotBugs
🐍 Python Pylint Black Flake8
📜 JavaScript/TypeScript ESLint Prettier Biome
🌐 Multi-linguagem SonarQube SonarCloud Super-Linter

analytics Relatório de verificação pelo SonarCloud

SonarCloud (e SonarQube) fornecem relatórios detalhados sobre:

  • 🔴 Bugs e vulnerabilidades de segurança
  • 🟡 Código duplicado
  • 🟢 Cobertura de testes
  • 🔵 Complexidade ciclomática
  • 📊 Dívida técnica estimada (em horas/dias)

auto_fix_high Automação de conformidade:

Podemos usar ferramentas para automação de atividades de verificação, e até mesmo aplicação automática de padrões de código, associando-as ao ciclo de desenvolvimento.

Ferramentas locais (hooks): pre-commit (Python/multi), husky (Node.js) e gradle (Java). 

# .husky/pre-commit (Node.js)
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

npx lint-staged

# package.json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": [
      "eslint --fix",
      "prettier --write"
    ]
  }
}

🤖 Serviços de integração contínua (GitHub Actions)

Você também pode usar serviços de integração contínua que executam as tarefas remotamente e notificam os resultados posteriormente, como GitHub Actions, GitLab CI, CircleCI ou Jenkins. 

name: CI - Conformidade e Testes

on:
  push:
    branches: [ develop, main ]
  pull_request:
    branches: [ main ]

jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      - name: Install dependencies
        run: npm ci
      - name: Lint
        run: npm run lint
      - name: Format check
        run: npm run format:check
      - name: Type check
        run: npm run type-check
      - name: Unit tests
        run: npm test -- --coverage
      - name: Security audit
        run: npm audit --production
check_circle Resultado da execução do workflow:
  • ✅ Lint passed (0 errors, 0 warnings)
  • ✅ Format check passed
  • ✅ Type check passed
  • ✅ 42 tests passed, 0 failed
  • ⚠️ 2 vulnerabilities found (1 low, 1 moderate) - not blocking

Status do PR: 🟢 Aprovado automaticamente para merge (após revisão manual do código).

🤖 Novas oportunidades com IA na revisão de código

smart_toy Ferramentas de IA para revisão de código

Novas ferramentas de IA para revisão de código integrada a fluxos de CI podem oferecer novas oportunidades de melhorias contínuas.

Exemplos: CodeRabbit.ai, GitHub Copilot, Amazon CodeWhisperer, CodeReview Bot (para pull requests).

Funcionalidades típicas:

  • 🔍 Identificação de problemas de estilo e boas práticas
  • 🐛 Sugestão de correções para bugs comuns
  • 📝 Geração automática de resumo do PR
  • ⚡ Sugestões de otimização de desempenho

🚀 Entregue rapidamente - Continuous Delivery

Em geral, CD (Continuous Delivery/Deployment) segue princípios semelhantes e muitas vezes é suportado pelas mesmas ferramentas de CI. A diferença está no destino final: produção.

docker Exemplo: Publicar uma imagem Docker do sistema

name: CD - Build e Push Docker Image

on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v2
      - name: Login to DockerHub
        uses: docker/login-action@v2
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}
      - name: Build and push
        uses: docker/build-push-action@v4
        with:
          push: true
          tags: diegosousa/cidade-virtual:${{ github.ref_name }}

Resultado: Ao criar uma tag v1.2.0, o GitHub Actions automaticamente constrói e publica a imagem Docker no Docker Hub, pronta para deploy.

tips_and_updates Para o Cidade Virtual (Vercel):

Em vez de Docker, o CD pode ser configurado diretamente com Vercel através da action amondnet/vercel-action, ou utilizando o Vercel CLI integrado ao workflow.

🔁 CI/CD como prática integradora

Atividades de CI/CD são práticas voltadas à automação de processos para melhoria da qualidade do processo e do produto de software.

warning Atenção:

Não faz sentido aplicar práticas automatizadas simplesmente porque outros usam. Busque cultivar uma cultura integrada entre desenvolvimento e entrega de qualidade. A automação deve servir a um propósito claro: reduzir retrabalho, aumentar confiança e acelerar feedback.

assignment Checklist de maturidade CI/CD para o Cidade Virtual

☐ Linter automático no commit
☐ Testes unitários no CI
☐ npm audit no CI
☐ Deploy automático em homologação
☐ Testes de integração no CI
☐ Deploy manual ou automático em produção
☐ Relatório de cobertura de testes
☐ Verificação de segurança (OWASP ZAP)

📋 Atividade de Checkout - Módulo 4

Plano de Integração de CI/CD

Você deverá criar um plano de integração de CI/CD para o projeto em desenvolvimento na disciplina de Projeto Integrador (Cidade Virtual).

O plano deve conter:

  • 📌 Processos que serão automatizados (ex: lint, testes, build, deploy)
  • 🎯 Objetivos e benefícios esperados com a automação
  • ⚠️ Desafios e impactos esperados na aplicação do processo
  • 🛠️ Ferramentas selecionadas (GitHub Actions, Husky, SonarCloud, etc.)
  • 📅 Cronograma de implementação (fases incremental)

tips_and_updates Dicas para a atividade:

  • Para além da automação das atividades, reflita sobre o impacto e como poderá contribuir para a melhoria da qualidade e agilidade no desenvolvimento.
  • Busque usar ferramentas e plataformas conhecidas, com grande comunidade e com uma visão de longo prazo e escalável (ex: GitHub Actions, GitLab CI, Vercel).
  • Comece com automações simples (linter, testes unitários) e evolua para integração e deploy.
