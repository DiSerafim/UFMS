🎯 Introdução ao Projeto Integrador III

O Projeto Integrador de Tecnologia da Informação III representa a culminação do ciclo de desenvolvimento iniciado nos semestres anteriores. Enquanto o PI-I focou na descoberta, modelagem e projeto da solução, e o PI-II concentrou-se no desenvolvimento da aplicação com frameworks, banco de dados e interface, o PI-III eleva o patamar ao abordar a integração, testes e garantia de qualidade da solução completa.

search PI-I

Descoberta, modelagem e projeto da solução. Definição de requisitos, DER, UML e protótipos.

code PI-II

Desenvolvimento da aplicação. Implementação front-end, back-end, banco de dados e versionamento.

verified PI-III

Integração, testes e garantia de qualidade. VVT, CI/CD, documentação e segurança.

flag Objetivo do PI-III

Conhecer e utilizar técnicas integradas de desenvolvimento de software para produção de sistemas resilientes, escaláveis, que atendam às suas especificações e estejam alinhados às necessidades dos clientes e da comunidade.

🔍 O que é VVT? Verificação, Validação e Teste

VVT é um conjunto de atividades sistemáticas realizadas durante todo o ciclo de vida do software para garantir que o produto final atenda aos requisitos especificados e às necessidades reais dos usuários. Embora muitas vezes usados como sinônimos, verificação, validação e teste têm propósitos distintos e complementares.

✅ Verificação (Verification)

A verificação é uma atividade estática (não envolve execução de código) que avalia artefatos do projeto para garantir que estejam corretos, completos e consistentes. Ela responde à pergunta: "Estamos construindo o produto corretamente?"

  • Técnicas comuns: Inspeções, revisões por pares, walkthroughs, análise estática de código.
  • Artefatos verificados: Documento de requisitos, diagramas UML, DER, protótipos, código-fonte.
  • Exemplo prático: Revisar se o diagrama de classes contempla todos os atributos identificados nos requisitos do sistema Cidade Virtual (usuário, comércio, serviço, evento, avaliação).

visibility Exemplo de Verificação - Cidade Virtual

Antes de codificar, a equipe realiza uma revisão técnica formal do DER (Diagrama Entidade-Relacionamento) para verificar se:

  • Todas as entidades mapeadas no levantamento estão representadas (USUARIO, COMERCIO, SERVICO, EVENTO, AVALIACAO).
  • Os relacionamentos estão corretos (1:N entre USUARIO e COMERCIO, USUARIO e SERVICO, etc.).
  • Os tipos de dados são apropriados (telefone como string, avaliação_media como decimal).

Resultado da verificação: Identifica-se que faltou a entidade CATEGORIA, que deve ser criada para melhor organizar os comércios e serviços.

✅ Validação (Validation)

A validação é uma atividade que busca garantir que o produto atende às necessidades reais dos usuários e resolve o problema proposto. Ela responde à pergunta: "Estamos construindo o produto certo?"

  • Técnicas comuns: Testes de aceitação com usuários, prototipação interativa, entrevistas de validação.
  • Diferencial: Envolve diretamente o público-alvo (moradores, comerciantes, autônomos).
  • Exemplo prático: Apresentar o protótipo funcional do Cidade Virtual para 3 comerciantes e 3 moradores e coletar feedback sobre a usabilidade e utilidade das funcionalidades.

groups Exemplo de Validação - Cidade Virtual

Uma sessão de validação com a Dona Maria (doceira autônoma) e o Seu João (mecânico) revela que:

  • Ambos têm dificuldade em fazer upload de fotos dos produtos/serviços → necessidade de simplificar o processo.
  • Moradores querem um campo de "distância aproximada" do comércio até sua localização → adicionar geolocalização.
  • Comerciantes solicitam um mural de "destaque pago" para pequenos anúncios → nova funcionalidade priorizada.

Resultado da validação: O backlog do projeto é ajustado para refletir as reais necessidades da comunidade antes do desenvolvimento avançado.

✅ Teste (Testing)

O teste é uma atividade dinâmica que envolve a execução do software com o objetivo de identificar defeitos, falhas e comportamentos inesperados. Ele responde à pergunta: "O sistema funciona conforme o esperado em diferentes cenários?"

straighten Testes Unitários

Verificam a menor parte testável do software (funções, métodos, classes). Exemplo: Testar se a função calcularAvaliacaoMedia([5,4,3]) retorna 4.0.

Ferramenta: Jest (JavaScript/TypeScript), JUnit (Java), PyTest (Python).

link Testes de Integração

Validam a comunicação entre módulos, componentes ou serviços. Exemplo: Testar se o endpoint POST /api/comercio insere corretamente os dados no banco.

Ferramenta: Supertest, Postman, Jest com integração.

dashboard Testes de Sistema

Avaliam o sistema como um todo, incluindo interface, performance e segurança. Exemplo: Simular 100 usuários acessando a página de busca simultaneamente.

Ferramenta: K6, JMeter, Cypress.

check_circle Testes de Aceitação

Realizados pelo cliente/usuário para validar se o sistema atende aos critérios de negócio. Exemplo: Comerciante cadastra seu negócio e verifica se aparece no mural.

Ferramenta: Cucumber (Gherkin), cenários manuais com checklist.

psychology Insight Avançado - Pirâmide de Testes

A Pirâmide de Testes (Mike Cohn) é um modelo que recomenda a proporção ideal de testes: muitos testes unitários (base), menos testes de integração (meio) e poucos testes end-to-end (topo). Para o Cidade Virtual, isso significa:

  • ✅ 70% testes unitários (regras de negócio, validações, cálculos)
  • ✅ 20% testes de integração (API + banco de dados)
  • ✅ 10% testes end-to-end (fluxos completos do usuário)

🔄 Relação entre Verificação, Validação e Teste

Na prática, essas atividades não são mutuamente exclusivas — elas se complementam ao longo do ciclo de vida do software. A tabela abaixo resume as principais diferenças:

Característica Verificação Validação Teste
Momento Antes da execução (estático) Após construção / com usuário Durante/ após execução
Envolve código? Não (documentos, diagramas) Sim (protótipo ou sistema final) Sim (execução do sistema)
Pergunta chave Construímos corretamente? Construímos o produto certo? Funciona como esperado?
Quem realiza? Equipe técnica, revisores Cliente, usuário, PO QA, desenvolvedores, automação
Exemplo no Cidade Virtual Revisar DER antes de codificar Morador testa busca por categoria Jest valida cálculo de avaliação

🚀 Técnicas Avançadas e Recomendações para Projetos de Extensão

rule Teste Baseado em Risco (Risk-Based Testing)

Priorize os testes com base no impacto e na probabilidade de falha. No Cidade Virtual, as funcionalidades de cadastro de comércio e busca por proximidade têm alto impacto (se falharem, o valor central do sistema é perdido). Invista mais testes nessas áreas.

smart_toy Teste de Mutação (Mutation Testing)

Introduz pequenas alterações no código (mutantes) para verificar se os testes existentes são capazes de detectá-las. Ferramentas como Stryker (JS) ou PIT (Java) ajudam a medir a eficácia real dos testes unitários.

Exemplo: Alterar if (nota >= 0 && nota <= 5) para if (nota > 0 && nota <= 5) e ver se o teste que valida nota=0 falha (indicando boa cobertura).

sync_alt Teste Contínuo (Continuous Testing)

Integrar os testes ao pipeline de CI/CD para que sejam executados automaticamente a cada commit ou pull request. Isso evita que código defeituoso chegue à produção. Para o Cidade Virtual, configurar GitHub Actions para rodar npm test antes de qualquer merge.

insights Insight para Projetos de Extensão

Em projetos comunitários como o Cidade Virtual, a validação com usuários reais é frequentemente mais crítica do que testes automatizados complexos. Priorize um equilíbrio: comece com testes unitários para as regras de negócio centrais, faça validações iterativas com a comunidade e, conforme o sistema amadurece, adicione testes de integração e carga.

Recomendação prática: Mantenha um checklist de validação comunitária com perguntas simples (ex: "Você conseguiu encontrar um eletricista perto da sua casa?") e realize sessões curtas a cada 15 dias.

🌍 VVT e Extensão Universitária: Impacto Social

A aplicação de práticas robustas de VVT em projetos de extensão não é apenas uma questão técnica — é um compromisso ético com a comunidade. Um sistema que falha ou gera informações incorretas pode prejudicar pequenos comerciantes e moradores que dependem dele.

handshake Confiança

Sistemas testados geram confiança na tecnologia como ferramenta de transformação social.

attach_money Economia Local

Falhas no Cidade Virtual podem fazer um comerciante perder vendas. Testes evitam esse risco.

public ODS 8 e 11

Qualidade de software impacta diretamente o trabalho decente (ODS 8) e comunidades sustentáveis (ODS 11).

warning Atenção!

A extensão universitária exige que a solução seja útil, acessível e confiável. Um software com bugs frequentes ou documentação ausente descredibiliza o projeto e afasta os usuários da comunidade. Invista em VVT como parte da responsabilidade social do projeto.

✍️ Exercício de Fixação - Aplicando VVT no Cidade Virtual

quiz Cenário para reflexão

Você é o responsável pela qualidade do projeto Cidade Virtual. Responda com base nos conceitos de VVT:

  1. Que técnica de verificação você aplicaria antes de começar a codificar a funcionalidade de "avaliação de comércios"?
  2. Como você validaria com os moradores se o sistema de busca por categoria atende às suas necessidades?
  3. Que tipos de teste você implementaria primeiro para garantir que o cadastro de usuários funcione corretamente?
  4. Como você adaptaria a pirâmide de testes para um projeto de extensão com recursos limitados?
🔎 Ver sugestão de respostas

1. Revisão por pares do DER e do diagrama de sequência que modela o fluxo de avaliação, além de inspeção dos critérios de aceite no documento de requisitos.

2. Sessão de validação com 5 moradores utilizando o protótipo funcional, observando se eles conseguem encontrar comércios por categoria sem ajuda externa.

3. Testes unitários para validação de campos (email, telefone, CPF/CNPJ) e testes de integração para o endpoint de cadastro com o banco de dados.

4. Priorizar testes unitários (baixo custo) e validação comunitária (alto valor), deixando testes de carga e mutação para fases mais maduras do projeto.
