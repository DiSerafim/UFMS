Tratamento de Interrupção.

INTERRUPÇÕES.

  • São mecanismos pelo qual outros módulos interrompem o processamento normal da CPU para avisar eventos como:
    • interrupção de programa (como traps)
    • interrupção de temporização (escalonamento de processo)
    • falha de hardware (c/ falta de energia)
    • interrupção de E/S (c/ fim de escrita no disco)
  • Quando ocorre uma interrupção, a CPU para o processamento do programa em execução e executa um pedaço de código chamado de tratador de interrupção
  • Em muitos casos, após a execução do tratador, a CPU volta a executar o programa interrompido

TRATADOR DE INTERRUPÇÕES.

  • Feito por um bloco especial de código associado a uma condição de interrupção específica
  • Chamado também de rotina de serviço de interrupção, ISR ou tratador de interrupção
  • Os handlers de interrupção são iniciados por interrupções de hardware, instruções de interrupção de software ou exceções de software
  • Usado para implementar drivers de dispositivo ou transições entre modos protegidos de operação, como chamadas de sistema
  • É um programa que determina a natureza da interrupção e que realiza o tratamento adequado. O controle é transferido para o tratador após:
    • O salvamento de algumas informações
      • É parte do sistema operacional

FUNÇÃO DO TRATADOR DE INTERRUPÇÕES.

  • Saber qual dispositivo lançou a interrupção e em que ponto do sistema operacional está o endereço inicial da rotina que trata esta interrupção, para que o processador possa executar esta rotina no endereço especificado pelo tratador e depois deixar que o processador volte ao seu curso normal de execução após a interrupção ter sido resolvida

INTERRUPÇÕES.

  • Em termos de fluxo de controle, a execução do tratador é um pouco como uma chamada de rotina, MAS
  • a chamada de rotina é iniciada por instruções do programa em execução
  • e o tratador de interrupção é NA MAIORIA das vezes assíncrono (SEM comunicação entre o programa interrompido e o tratador)
  • MAS existe interrupção síncrona, como o caso do Trap

SUPORTE DE HARDWARE.

  • Tipicamente, o hardware detecta a interrupção, aguarda o final da execução da instrução corrente e aciona o tratador, salvando antes o contexto de execução do processo interrompido
  • Para reiniciar a execução, é necessário salvar o Contador de Programa e outros registradores de status. Os registradores com dados do programa devem ser salvos pelo próprio tratador (ou seja, pelo software), caso ele os utilize.
  • Em muitas arquiteturas, existe uma pilha independente associada ao tratamento de interrupções

INTERRUPÇÕES DE HARDWARE.

  • São geradas pelo hardware
  • Por exemplo, para indicar overflow em operações aritméticas, ou acesso a regiões de memória não permitidas
  • Essas são situações em que o programa não teria como prosseguir
  • O hardware sinaliza uma interrupção para passar o controle para o tratador de interrupção, que tipicamente termina a execução do programa

INTERRUPÇÕES DE RELÓGIO.

  • É uma interrupção comum de hardware
  • O mecanismo permite ao sistema operacional atribuir quotas de tempos de execução (fatias de tempo) para cada um dos processos em um sistema multiprograma
  • A cada interrupção do relógio, o tratador pode verificar se a fatia de tempo do processo em execução já se esgotou e, se for o caso, suspendê-lo e acionar o escalonador para que escolha outro processo para colocar em execução.

INTERRUPÇÕES TRAP.

  • É uma interrupção de programa
  • São interrupções que ocorrem em consequência da instrução executada no processador
  • Por exemplo, durante o tratamento de um programa ocorre divisão por zero
  • São síncronas e é até possível o programa passar algum parâmetro para o tratador

CHAMADA DE SISTEMA.

  • É o mecanismo pelo qual um programa de usuário solicita um serviço do sistema operacional
  • Por exemplo, para acessar o disco rígido, a criação e a execução de novos processos e comunicação com serviço do SO como escalonamento de processo
  • É uma interface essencial entre um processo e o sistema operacional

EXEMPLO ASSEMBLY DE INTERRUPÇÃO: IA-32.

  • A instrução int n do assembly IA-32 gera um trap
  • No Linux, antes de executar essa instrução, o número da chamada deve ser colocado no registrador %eax, e os argumentos nos registradores %ebx, %ecx, %edx, %esi e %edi
  • Depois que o sistema operacional executa o serviço requisitado, o controle retorna à instrução seguinte int, com o valor de retorno em %eax
