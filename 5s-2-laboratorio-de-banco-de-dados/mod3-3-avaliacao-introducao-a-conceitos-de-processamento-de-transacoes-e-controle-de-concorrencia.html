Pergunta 1

O que acontece ao iniciar uma transação com BEGIN no PostgreSQL?

  • a. A transação começa e todas as operações seguintes fazem parte dela até o COMMIT ou ROLLBACK.
  • b. A transação inicia e os dados são automaticamente salvos.
  • c. Os dados são imediatamente gravados no banco.
  • d. A transação é iniciada, mas não é possível executar comandos até um COMMIT.
Resposta: a. ✅

📌 Explicação:

  • Quando você inicia uma transação com BEGIN no PostgreSQL, todas as operações subsequentes (como INSERT, UPDATE, DELETE) são agrupadas em uma unidade lógica.
  • As alterações não são finalizadas imediatamente no banco de dados. Elas permanecem temporárias até que um COMMIT confirme as mudanças ou um ROLLBACK as desfaça.
  • Isso garante atomicidade: ou todas as operações da transação são aplicadas (commit), ou nenhuma é (rollback).
                BEGIN;  
                UPDATE conta SET saldo = saldo - 100 WHERE id = 1;  
                UPDATE conta SET saldo = saldo + 100 WHERE id = 2;  
                COMMIT; -- Confirma as alterações

Pergunta 2

Como um savepoint é utilizado em uma transação no PostgreSQL?

  • a. Para marcar um ponto na transação que permite reverter apenas até esse ponto usando ROLLBACK TO
  • b. Para confirmar parcialmente as operações realizadas
  • c. Para reiniciar uma transação a partir do início
  • d. Para finalizar uma transação sem aplicar alterações
Resposta: a. ✅

📌 Explicação:

  • O SAVEPOINT é usado para criar um ponto de restauração nomeado dentro de uma transação.
  • Se ocorrer um erro ou uma condição específica, você pode reverter apenas parte da transação usando ROLLBACK TO [nome_do_savepoint], mantendo as operações válidas feitas antes do savepoint.
  • Isso permite controle granular em transações complexas, onde é necessário desfazer apenas certas etapas, sem cancelar toda a transação.
                BEGIN;
                INSERT INTO clientes (nome) VALUES ('Maria');
                SAVEPOINT ponto1;
                UPDATE pedido SET valor = 100 WHERE id = 1;
                
                -- Se ocorrer um erro no UPDATE:
                ROLLBACK TO ponto1;

                -- O INSERT de 'Maria' permanece válido, e a transação continua
                COMMIT;

Pergunta 3

Para configurar uma conexão JDBC em uma aplicação Java, qual das seguintes opções é necessária?

  • a. Instalar um servidor de aplicação Java.
  • b. Utilizar a anotação @JDBCConnection na classe.
  • c. Carregar o driver JDBC e fornecer a URL do banco de dados, usuário e senha.
  • d. Configurar um servidor FTP para a transferência de dados.
Resposta: c. ✅

📌 Explicação:

  • Para configurar uma conexão JDBC em Java, é essencial:
  • Carregar o driver JDBC adequado ao banco de dados (ex: Class.forName("org.postgresql.Driver") ou via dependência automática em JDBC 4.0+).
  • Fornecer a URL de conexão, usuário e senha para estabelecer a comunicação com o banco via DriverManager.getConnection(url, user, password).
                // Carrega o driver (JDBC 4.0)
                Class.forName("org.postgresql.Driver");

                // Configura URL, usuário e senha
                String url = "jdbc:postgresql://localhost:5432/meu_banco";
                Connection conexao = DriverManager.getConnection(url, "usuario", "senha");

Pergunta 4

Qual é o comportamento padrão do PostgreSQL em relação a transações?

  • a. Ele permite apenas uma transação por conexão.
  • b. Ele opera automaticamente em modo de transação explícita.
  • c. Ele sempre exige o uso de BEGIN para qualquer comando.
  • d. Ele opera no modo de transação implícita, em que cada comando automaticamente sofre um “COMMIT”, salvando as alterações no banco de dados de forma permanente.
Resposta: d. ✅

📌 Explicação:

  • Por padrão, o PostgreSQL utiliza o modo de transação implícita (auto-commit). Isso significa que, se você não iniciar uma transação explicitamente com BEGIN ou START TRANSACTION, cada comando SQL (como INSERT, UPDATE, DELETE) é tratado como uma transação única e isolada, sendo automaticamente confirmado (COMMIT) após sua execução.
  • Por exemplo, ao executar DELETE FROM tabela WHERE id = 1;, a exclusão é imediatamente permanente, sem necessidade de COMMIT explícito.
                -- Modo implícito (padrão)
                INSERT INTO clientes (nome) VALUES ('João'); -- Commit automático!

                -- Modo explícito (requer BEGIN):
                BEGIN;
                UPDATE produtos SET preco = 50 WHERE id = 1;
                COMMIT;

Pergunta 5

Qual das seguintes opções é uma anotação usada no Hibernate para mapear uma classe Java para uma tabela do PostgreSQL?

  • a. @Entity
  • b. @PrimaryKey
  • c. @Table
  • d. @Column
Resposta: a. ✅
  • @Entity: É a anotação obrigatória para marcar uma classe Java como uma entidade persistente, indicando que ela será mapeada para uma tabela no banco de dados. Sem ela, o Hibernate não reconhece a classe como parte do modelo de dados.
                @Entity
                @Table(name = "clientes"); // Opcional
                public class Cliente {
                    @Id
                    private Long id;
                    @Column(name = "nome_completo")
                    private String nome;
                }

Pergunta 6

Se um COMMIT for executado com sucesso, o que acontece com a transação?

  • a. O banco de dados entra em modo de apenas leitura.
  • b. A transação entra em espera por mais comandos.
  • c. A transação é finalizada e as alterações são aplicadas ao banco de dados.
  • d. Ela permanece ativa até que um novo comando seja emitido.
Resposta: c. ✅

📌 Explicação:

  • O comando COMMIT finaliza uma transação com sucesso, tornando todas as alterações realizadas durante ela permanentes no banco de dados.
  • Após o COMMIT, a transação é encerrada e não pode mais sofrer ROLLBACK (a menos que haja um recurso específico de flashback ou backups).
                BEGIN;
                UPDATE conta SET saldo = saldo - 200 WHERE id = 1;
                UPDATE conta SET saldo = saldo + 200 WHERE id = 2;
                COMMIT; -- Aqui, as alterações são salvas permanentemente!

Pergunta 7

Quando um ROLLBACK é automaticamente executado no PostgreSQL?

  • a. Quando a conexão com o banco de dados é fechada
  • b. Quando a transação é explicitamente finalizada com COMMIT
  • c. Quando ocorre um erro durante a execução da transação
  • d. Quando a transação excede o tempo limite configurado
Resposta: a. ❌ Resposta: c. ✅

📌 Explicação:

  • O PostgreSQL executa um ROLLBACK automático se uma conexão for encerrada (ex.: cliente desconecta, falha de rede) enquanto uma transação está em aberto. Isso garante que alterações não confirmadas não persistam no banco.
  • Exemplo: Se você inicia uma transação com BEGIN, faz um INSERT, mas fecha a conexão antes de um COMMIT, o PostgreSQL reverte automaticamente a inserção.

Pergunta 9

Qual é a função do comando COMMIT em uma transação no PostgreSQL?

  • a. Finalizar a transação e aplicar as alterações ao banco de dados
  • b. Cancelar todas as operações realizadas na transação
  • c. Ignorar as alterações e continuar a transação
  • d. Finalizar a transação e reverter as alterações
Resposta: a. ✅

📌 Explicação:

  • O comando COMMIT finaliza uma transação com sucesso, tornando todas as alterações realizadas durante a transação permanentes no banco de dados. Após o COMMIT, não é possível reverter as mudanças (a menos que haja recursos específicos de recuperação, como backups).
                BEGIN;
                UPDATE conta SET saldo = 500 WHERE id = 1;
                COMMIT; -- As alterações são salvas permanentemente!

Pergunta 10

Para estabelecer uma conexão Java com um banco de dados PostgreSQL usando JDBC, qual URL de conexão é correta?

  • a. jdbc:mysql://localhost:5432/mydb
  • b. jdbc:oracle:thin:@localhost:1521:mydb
  • c. jdbc:sqlserver://localhost:1433;databaseName=mydb
  • d. jdbc:postgresql://localhost:5432/mydb
Resposta: d. ✅

📌 Explicação:

  • A URL de conexão JDBC para PostgreSQL segue o formato:
  • jdbc:postgresql://[host]:[port]/[database], onde:
    • postgresql indica o driver específico do PostgreSQL.
    • localhost é o host onde o banco está hospedado.
    • 5432 é a porta padrão do PostgreSQL.
    • mydb é o nome do banco de dados.
                String url = "jdbc:postgresql://localhost:5432/mydb";  
                Connection conexao = DriverManager.getConnection(url, "usuario", "senha");
