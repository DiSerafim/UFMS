O que é um DBA?.

O Database Administrator (DBA) é o profissional responsável pela administração e manutenção dos bancos de dados de uma organização.

Seu papel envolve garantir que os dados sejam armazenados, acessados e manipulados de forma eficiente e segura.

Responsabilidades principais: O DBA gerencia o banco de dados, realiza backups, monitora o desempenho, define políticas de segurança e otimiza o acesso aos dados.

Ele também administra as permissões de usuários, assegurando que apenas pessoas autorizadas possam acessar ou modificar informações sensíveis.

Por que o papel do DBA é fundamental?.

Integridade dos dados: O DBA é responsável por garantir que os dados estejam sempre precisos e consistentes, evitando erros que possam comprometer a qualidade da informação.

Segurança dos dados: O DBA define políticas de acesso e protege os dados contra acessos não autorizados ou atividades maliciosas, como fraudes ou invasões.

Disponibilidade: O DBA mantém o banco de dados disponível para os usuários, prevenindo e solucionando falhas para que o sistema funcione continuamente. Isso é essencial para as operações diárias da empresa, evitando interrupções que podem resultar em prejuízos financeiros.

Impacto nas organizações.

Continuidade dos negócios: O trabalho do DBA é essencial para garantir que as operações da empresa não sejam interrompidas. Se o banco de dados estiver fora do ar ou corrompido, isso pode paralisar atividades essenciais, afetando diretamente os resultados da organização.

Proteção das informações: A segurança dos dados é uma preocupação crescente nas empresas. O DBA garante que dados críticos, como informações de clientes e transações financeiras, estejam protegidos contra perda ou roubo.

Otimização de desempenho: O DBA monitora e ajusta o banco de dados para melhorar o desempenho das aplicações que dependem dele. Isso inclui a otimização de consultas, a reorganização de índices e a alocação eficiente de recursos de hardware.

Principais Tarefas e Responsabilidades do DBA.

Definição de Esquema: criar e manter o esquema inicial do banco de dados utilizando DDL (Data Definition Language).

Estrutura de Armazenamento e Definição de Métodos de Acesso: como os dados são armazenados em disco, incluindo o uso de índices para melhorar a eficiência das consultas.

  • Tarefa do DBA: Escolher a estrutura de armazenamento adequada e definir índices para melhorar a performance de buscas.

Modificação de Esquema e Organização Física: adaptar o banco de dados às mudanças nas necessidades do negócio.

  • Tarefa do DBA: Atualizar o esquema e reorganizar o armazenamento dos dados para manter a eficiência.

Concessão de Autorizações para Acesso aos Dados: garantir que diferentes usuários tenham apenas os acessos necessários às informações.

  • Tarefa do DBA: Utilizar comandos como GRANT e REVOKE para definir quem pode acessar, modificar ou excluir dados.

Manutenção de Rotina: criar cópias de segurança dos dados periodicamente.

  • Tarefa do DBA: Realizar backups regulares e monitorar o espaço em disco.
  • Política de recuperação de desastres.
  • Monitoramento de Tarefas: Garantir que as operações de usuários não afetem a performance global do sistema.

Importância dos Backups.

Realizar backups periódicos é essencial para garantir a segurança e a integridade dos dados em um banco de dados. Os motivos para essa prática incluem:

  • Prevenção contra Perda de Dados:
    • Incidentes como falhas de hardware, ataques cibernéticos, ou erros humanos podem resultar na perda de dados importantes. Ter backups regulares garante que seja possível restaurar as informações ao estado anterior ao incidente.

Recuperação de Desastres:

  • Em casos de desastres, como incêndios ou enchentes, onde a infraestrutura física é danificada, os backups permitem a restauração dos dados em um novo local. Isso é vital para a continuidade dos negócios.

Proteção contra Erros Humanos:

  • É comum que erros ocorram durante operações no banco de dados, como exclusões ou modificações acidentais. Com um backup, é possível reverter para um estado anterior.

Cumprimento de Normas e Regulamentações:

  • Em muitos setores, existe a exigência legal de manter cópias de dados para fins de conformidade. Realizar backups periódicos ajuda a atender a essas normas.

Realizar esses backups regularmente, de preferência automatizando o processo, é uma prática recomendada para qualquer administrador de banco de dados. Isso ajuda a minimizar os impactos de falhas e a garantir a segurança das informações.

Backup no PostgreSQL.

Para realizar um backup de um banco de dados no PostgreSQL, é utilizado o comando pg_dump.

Este comando cria um arquivo com uma cópia do banco de dados, que pode ser utilizado para restaurar os dados posteriormente.

pg_dump -U usuario -W -F c -b -v -f /caminho/do/backup/meuBanco.backup meuBanco
  • -U usuario: Nome do usuário do banco de dados.
  • -W: Solicita a senha do usuário antes de executar o backup.
  • -F c: Especifica o formato do backup. Nesse caso, o formato é "custom" (c), que permite uma restauração mais rápida e flexível.
  • -b: Inclui os dados binários no backup.
  • -v: Ativa o modo verboso, exibindo informações detalhadas sobre o processo.
  • -f /caminho/do/backup/meuBanco.backup: Especifica o local e o nome do arquivo de backup.
  • meuBanco: Nome do banco de dados a ser copiado.

Para fazer o backup do banco de dados "loja", o comando seria:

pg_dump -U postgres -W -F c -b -v -f /home/usuario/backup/loja.backup loja

Após a execução, será solicitado que o usuário informe a senha do banco de dados, e o arquivo "loja.backup" será criado no diretório especificado
