Materiais

As transações são um grupo que contém uma ou mais operações lógicas, como, por exemplo, uma transferência de uma conta bancária para outra. Nesse caso, as operações são, respectivamente de criação, leitura, atualização e deleção (ou, em Inglês, a sigla CRUD – Create – Read – Update – Delete).

Contudo, o principal problema de uma base de dados que não usa a estrutura ACID é a abundante quantidade de dados que é processada diariamente, além da lentidão que eles podem ter ao serem processados. E, você não quer esperar um tempo longo para realizar uma transferência bancária, não é?

Por isso, para simplificar esses procedimentos, é utilizada a estrutura ACID, para que os dados sejam armazenados de uma forma segura e que garanta o processamento dos dados de forma eficiente no servidor.

A sigla ACID define os quatro pilares necessários para a realização de uma transação em um sistema de banco de dados. São elas:

  • Atomicidade;
  • Consistência;
  • Isolamento;
  • Durabilidade.

Se as quatro propriedades exibidas acima forem seguidas de forma correta, as suas transações estão compatíveis com a estrutura ACID. Esse é o conceito de ACID Compliance, estar em conformidade com os pilares das transações.

  1. Descreva o que é Atomicidade.
    • A atomicidade é a propriedade que garante que todas as operações de uma transação sejam concluídas (COMMIT) com sucesso ou, em caso de falha, nenhuma delas será aplicada (ROLLBACK). É o conceito de "tudo ou nada".
      • Exemplo: Em uma transação bancária, o débito de uma conta e o crédito de outra devem ocorrer juntos ou nenhum deles deve acontecer.
        • Débito de R$500,00 da conta A.
        • Crédito de R$500,00 na conta B.
      • Se o sistema falhar após o débito da conta A e antes do crédito na conta B, a atomicidade garante que a transação inteira seja cancelada. O saldo da conta A é restaurado e nenhum valor é creditado na conta B.
  2. Descreva o que diferencia o Isolamento da Durabilidade.
    3. Isolamento
    • O isolamento garante que as transações concorrentes executadas de forma simultaneamente, não interfiram umas nas outras. Cada transação age como se fosse a única sendo executada no banco de dados, mesmo que outras estejam sendo executadas no momento. Evitando problemas como:
      • Leitura suja: Ler dados de uma transação não confirmada.
      • Leitura não repetível: Dados alterados por outra transação durante uma mesma operação.
    • Ex.:
      • Se duas transações tentam atualizar o saldo da mesma conta ao mesmo tempo, o isolamento garante que somente uma verá o resultado final após a outra ser concluída (Como uma transação feita no caixa eletrônico).
    • Gerencia concorrência entre transações.
    • Evita interferência entre operações simultâneas.
    Durabilidade
    • A durabilidade garante que uma vez confirmada uma transação (COMMIT) seus efeitos persistirão permanentemente no banco de dados, mesmo em casos de falhas do sistema como queda de energia. Os dados são salvos em armazenamento não volátil como disco rígido.
    • Ex.:
      • Após uma transferência bancária ser confirmada os novos dados da conta A e conta B devem permanecer atualizados mesmo que o servidor do banco de dados reinicie subitamente
    • Garante persistência dos dados após confirmação.
    • Protege contra perda de dados por falhas físicas ou lógicas.

Atomicidade: "Tudo ou nada".

Isolamento: Transações não se atrapalham.

Durabilidade: Dados salvos para sempre após confirmação.
