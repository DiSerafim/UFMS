Pergunta 1

Qual das seguintes opções NÃO é um tipo de evento que pode disparar um trigger em PostgreSQL?

  • a. DELETE
  • b. SELECT
  • c. UPDATE
  • d. INSERT
Resposta: b. ✅

📌 Explicação:

  • Em PostgreSQL, os triggers são acionados por operações de INSERT, UPDATE e DELETE, mas não por SELECT, pois consultas de leitura não modificam os dados.

Pergunta 2

Qual das seguintes opções é verdadeira sobre triggers em PostgreSQL?

  • a. Triggers são executados manualmente pelo administrador do banco de dados.
  • b. Triggers são utilizados apenas para leitura de dados.
  • c. Triggers não podem acessar outras tabelas.
  • d. Triggers podem ser usados para validar dados antes de uma inserção.
Resposta: d. ✅

📌 Explicação:

  • Triggers do tipo BEFORE INSERT são comumente usados para:
    • Validar regras de negócio (ex.: checar se um e-mail é válido).
    • Rejeitar operações se os dados forem inválidos (usando RAISE EXCEPTION).

Pergunta 3

Qual é a sintaxe correta para criar uma função que retorna um tipo TABLE em PostgreSQL?

  • a. CREATE FUNCTION function_name() RETURNS SETOF table_name AS
    • LANGUAGE plpgsql;
  • b. CREATE FUNCTION function_name() RETURNS TABLE AS
    • LANGUAGE plpgsql;
  • c. CREATE FUNCTION function_name() RETURNS TABLE (column1 type1, column2 type2) AS
    • LANGUAGE plpgsql;
  • d. CREATE FUNCTION function_name() RETURNS RECORD AS
    • LANGUAGE plpgsql;
Resposta: c. ✅

📌 Explicação:

  • Permite definir explicitamente a estrutura da tabela retornada

Pergunta 4

Como você desativa temporariamente um trigger em PostgreSQL?

  • a. DELETE TRIGGER trigger_name
  • b. DISABLE TRIGGER trigger_name
  • c. UPDATE TRIGGER trigger_name SET DISABLE
  • d. ALTER TABLE table_name DISABLE TRIGGER trigger_name
Resposta: d. ✅

📌 Explicação:

  • A sintaxe correta para desativar um trigger temporariamente é:
    • ALTER TABLE nome_da_tabela DISABLE TRIGGER nome_do_trigger;
  • Para desativar todos os triggers de uma tabela:
    • ALTER TABLE nome_da_tabela DISABLE TRIGGER ALL;

Pergunta 5

Qual a finalidade de um trigger BEFORE UPDATE em PostgreSQL?

  • a. Executar uma ação depois de um registro ser inserido
  • b. Executar uma ação antes de um registro ser deletado
  • c. Executar uma ação antes de um registro ser atualizado
  • d. Executar uma ação depois de um registro ser atualizado
Resposta: d. ❌ Resposta: c. ✅
  • Executar ações antes que a operação de UPDATE seja concluída
    • O trigger é acionado após a solicitação de atualização, mas antes que as alterações sejam efetivamente aplicadas ao banco de dados
  • Casos de uso comuns:
    • Validar os novos valores antes da atualização
    • Modificar os valores que serão armazenados
    • Realizar verificações de integridade complexas
    • Registrar informações de auditoria
    • Impedir a atualização em certas condições (lançando uma exceção)
  • Diferença chave:
    • BEFORE UPDATE: Executa ANTES da operação
    • AFTER UPDATE: Executa DEPOIS que a operação já foi concluída

Pergunta 6

No PostgreSQL, a cláusula FOR EACH ROW em triggers executa a ação da trigger apenas uma vez, independentemente de quantas linhas forem afetadas pelo comando SQL.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Falso. ✅

📌 Explicação:

  • FOR EACH ROW faz com que o trigger seja executado uma vez para cada linha afetada pelo comando SQL
  • Exemplo: Se um UPDATE afetar 100 linhas, o trigger será executado 100 vezes (uma para cada linha)

Pergunta 7

Qual é a finalidade do comando LANGUAGE ao criar uma função em PostgreSQL?

  • a. Define o idioma do banco de dados
  • b. Define a linguagem de programação utilizada na função
  • c. Define o conjunto de dados retornados pela função
  • d. Define os parâmetros da função
Resposta: b. ✅

📌 Explicação:

  • LANGUAGE em funções PostgreSQL especifica qual linguagem de procedimento será usada para escrever o corpo da função. As principais características são:
    • Finalidade principal:
      • Indica ao PostgreSQL qual interpretador/processador usar para executar o código da função
      • Determina a sintaxe e capacidades disponíveis no corpo da função
    • Linguagens comuns:
      • plpgsql (Padrão, linguagem procedural do PostgreSQL)
      • sql (Para funções simples em SQL puro)
      • plpython, plperl, pljava (Para outras linguagens)

Pergunta 8

Associe as características das funções e procedimentos com suas definições:

                Altera propriedades de uma função, como o proprietário (...).
                Executa operações, mas não retorna valores (...).
                Executa operações no banco de dados e retorna um valor (...).
                Permite modificar uma função existente sem precisar removê-la primeiro (...).

Opções: CREATE OR REPLACE FUNCTION, Função, ALTER FUNCTION, Procedimento.

Resposta: ✅ 
                Altera propriedades de uma função, como o proprietário ALTER FUNCTION.
                Executa operações, mas não retorna valores Procedimento.
                Executa operações no banco de dados e retorna um valor Função.
                Permite modificar uma função existente sem precisar removê-la primeiro CREATE OR REPLACE FUNCTION.

📌 Explicação:

  • → ALTER FUNCTION
    • (Comando usado para modificar propriedades de uma função existente, como dono, schema ou atributos de segurança)
  • → PROCEDURE
    • (No PostgreSQL, procedimentos são criados com CREATE PROCEDURE e não retornam valores, diferentemente das funções. São usados para ações como transações ou DML.)
  • → FUNCTION
    • (Funções são definidas com CREATE FUNCTION, realizam operações e retornam um valor através de RETURNS.)
  • → CREATE OR REPLACE FUNCTION
    • (Esta sintaxe atualiza a definição de uma função mantendo suas permissões e dependências intactas.)

Pergunta 9

Associe os tipos de retorno de funções com suas descrições:

                Retorna um conjunto de registros, ou seja, várias linhas (...).
                Retorna uma coleção de valores organizados em uma estrutura de array (...).
                Retorna um único valor simples, como um número inteiro ou texto (...).
                Retorna um registro com múltiplas colunas (...).

Opções: Escalar, SETOF, Array, Record.

Resposta: ✅ 
                Retorna um conjunto de registros, ou seja, várias linhas SETOF.
                Retorna uma coleção de valores organizados em uma estrutura de array Array.
                Retorna um único valor simples, como um número inteiro ou texto Escalar.
                Retorna um registro com múltiplas colunas Record.

📌 Explicação:

  • → SETOF ou RETURNS TABLE
    • (Exemplo: RETURNS SETOF tabela ou RETURNS TABLE(col1 tipo1, col2 tipo2) - usado para funções que retornam múltiplas linhas como resultados)
  • → ARRAY
    • (Exemplo: RETURNS INTEGER[] - retorna um array de inteiros, útil para agregações ou listas de valores)
  • → Scalar (tipos básicos)
    • (Exemplo: RETURNS INTEGER, RETURNS VARCHAR, RETURNS BOOLEAN - para funções que devolvem um único valor atômico)
  • → RECORD ou COMPOSITE TYPE
    • (Exemplo: RETURNS RECORD ou RETURNS meu_tipo_composto - usado quando a função retorna uma linha com várias colunas de tipos diferentes)

Pergunta 10

Qual a principal função de um trigger em PostgreSQL?

  • a. Realizar backup do banco de dados
  • b. Permitir a criação de índices
  • c. Criar novas tabelas
  • d. Executar automaticamente uma ação em resposta a um evento
Resposta: d. ✅

📌 Explicação:

  • Executar automaticamente ações quando ocorrem eventos específicos no banco de dados, como:
    • Operações DML: INSERT, UPDATE ou DELETE
    • Operações DDL: CREATE, ALTER ou DROP (em versões mais recentes)
  • Características essenciais:
    • São acionados automaticamente pelo SGBD
    • Operam no nível do banco de dados, não da aplicação
    • Podem ser executados antes (BEFORE) ou depois (AFTER) do evento principal
    • Trabalham no contexto da transação em curso
  • Casos de uso típicos:
    • Validação complexa de dados
    • Manutenção de dados derivados (ex.: atualizar totais)
    • Auditoria/log de alterações
    • Replicação de dados entre tabelas
    • Aplicação de regras de negócio complexas
