Conceito de Segurança em Banco de Dados.

Segurança em banco de dados envolve a aplicação de políticas e mecanismos que garantem a proteção dos dados contra acessos não autorizados.

Utiliza mecanismos de autorização para controlar quem pode acessar ou manipular informações específicas no banco de dados.

Exemplo: sistema financeiro.

Mecanismos de Autorização.

No contexto de segurança em bancos de dados, privilégios são permissões que podem ser concedidas a usuários para realizar operações específicas em um banco de dados.

Esses privilégios garantem o controle sobre quem pode acessar e modificar os dados ou os esquemas.

Permissões são concedidas para ações específicas: leitura (SELECT), inserção (INSERT), atualização (UPDATE) e exclusão (DELETE).

A manipulação de esquemas em SQL envolve permissões que permitem aos usuários modificar a estrutura do banco de dados, criando ou alterando objetos, como tabelas, índices, visões, etc.

  • CREATE: Permissão para criar novos objetos no banco de dados, como tabelas, índices ou visões.
  • ALTER:Permissão para modificar a estrutura de objetos existentes, como adicionar ou remover colunas em uma tabela.
  • DROP: Permissão para excluir objetos do banco de dados, como tabelas ou visões

Comando GRANT.

O comando GRANT em SQL é usado para conceder privilégios a usuários ou papéis (roles). A sintaxe básica é a seguinte:

            GRANT lista de privilégios> ON nome da tabela ou view> TO usuário ou role>;
Exemplos de uso do comando GRANT.

Concedendo o privilégio de leitura a um usuário:

            GRANT SELECT ON tabela_clientes TO usuario_leitura;
            
            Neste exemplo, o usuário usuario_leitura poderá realizar consultas (SELECT) na tabela tabela_clientes.

Concedendo o privilégio de atualização em colunas específicas:

            GRANT UPDATE (preco) ON tabela_produtos TO usuario_atualizador;
            
            Aqui, o privilégio UPDATE é concedido apenas para a coluna preco na tabela tabela_produtos.
            O usuário usuario_atualizador poderá modificar os preços, mas não terá permissão para atualizar outras colunas.

Para conceder privilégios de SELECT e UPDATE ao usuário na tabela tabela_vendas, você pode usar o comando GRANT da seguinte forma:

            GRANT SELECT, UPDATE ON tabela_vendas TO usuario_completo;

Concedendo todos os privilégios disponíveis:

            GRANT ALL PRIVILEGES ON tabela_vendas TO usuario_completo;
            
            O usuário usuario_completo receberá todos os privilégios (como SELECT, INSERT, UPDATE, DELETE) sobre a tabela tabela_vendas.

Comando REVOKE.

O comando REVOKE é usado para remover privilégios que foram concedidos anteriormente a um usuário ou papel. A sintaxe básica é:

            REVOKE <lista de privilégios> ON <nome da tabela ou view> FROM <usuário ou role>;
Exemplos de uso do comando REVOKE

Removendo o privilégio de leitura de um usuário:

            REVOKE SELECT ON tabela_clientes FROM usuario_leitura;

            Este comando revoga o privilégio SELECT do usuário usuario_leitura na tabela tabela_clientes, impedindo-o de realizar consultas na tabela.

Revogando todos os privilégios concedidos:

            REVOKE ALL PRIVILEGES ON tabela_vendas FROM usuario_completo;
            
            Neste exemplo, o comando remove todos os privilégios concedidos anteriormente ao usuário usuario_completo na tabela tabela_vendas.
Implicações do comando REVOKE

Ao revogar privilégios, especialmente quando se usa o comando REVOKE ALL PRIVILEGES, os usuários ou papéis afetados perdem o acesso para executar ações específicas nos objetos do banco de dados.

Além disso, quando um privilégio é revogado de um usuário que o concedeu a outro, todos os privilégios concedidos por esse usuário também são revogados (revogação em cascata).

Roles (papéis) no controle de acesso.

Roles (papéis) no controle de acesso são uma forma de simplificar e organizar a administração de permissões em um banco de dados, especialmente em cenários com muitos usuários e diferentes níveis de acesso.

Em vez de conceder privilégios individualmente a cada usuário, os privilégios podem ser agrupados em um "role" (papel), e então o role é atribuído aos usuários.

Isso facilita a administração, pois os privilégios podem ser gerenciados centralmente através dos roles.

Vantagens de usar roles

Facilitam a administração de permissões: ao invés de configurar privilégios para cada usuário separadamente, os privilégios podem ser atribuídos a um role, e o role é então concedido aos usuários.

Escalabilidade: permitem gerenciar permissões de forma eficiente em ambientes com muitos usuários.

Segurança centralizada: permissões são gerenciadas em um único lugar, reduzindo o risco de configurações de acesso incorretas.

Criação e concessão de roles

Criando um role

O comando CREATE ROLE é usado para criar um novo role no banco de dados:

            CREATE ROLE instrutor;
Concedendo privilégios a um role

Este comando concede ao role instrutor o privilégio de leitura (SELECT) na tabela tabela. Qualquer usuário associado ao role instrutor terá essa permissão.

            GRANT SELECT ON tabela TO instrutor;
Associando um role a um usuário

Depois de configurar os privilégios do role, ele pode ser associado a um usuário com o comando GRANT.

            GRANT instrutor TO usuario;
            
            Esse comando concede ao usuário todos os privilégios do role instrutor. A partir desse momento, o usuário terá as mesmas permissões configuradas no role.
Exemplos de roles 
            CREATE ROLE DBA;
            GRANT ALL PRIVILEGES ON banco_de_dados TO DBA;
            GRANT DBA TO admin;


            CREATE ROLE Estagiario;
            GRANT SELECT ON clientes TO Estagiario;
            GRANT Estagiario TO Joao;

Autorização sobre views.

Vantagens de usar views para controle de acesso

  • Simplificação das consultas
  • Manutenção da segurança
  • Controle granular de acesso aos dados

Vamos criar uma view que mostra apenas os dados dos funcionários que são gerentes.

            CREATE VIEW gerentes AS
            SELECT nome, salario
            FROM funcionarios
            WHERE cargo = 'Gerente';

Concedendo privilégios em views

            GRANT SELECT ON gerentes TO usuario;
Autorização em nível de linha

É um mecanismo de controle de acesso que permite definir quais linhas (ou tuplas) de uma tabela um usuário pode visualizar ou manipular.

Diferente dos privilégios tradicionais, que aplicam permissões à tabela inteira ou a colunas específicas, a autorização em nível de linha oferece uma maneira de controlar o acesso com maior precisão.

            CREATE VIEW vendas_vendedor1 AS
            SELECT * FROM registros_vendas WHERE vendedor_id = 1;
            GRANT SELECT ON vendas_vendedor1 TO vendedor1_user;

Práticas de segurança recomendadas.

Princípio do mínimo privilégio: conceder aos usuários apenas os privilégios estritamente necessários para a execução de suas tarefas.

Auditoria e registro de acessos: auditoria é o processo de monitorar e registrar atividades realizadas no banco de dados, como operações de leitura, escrita, atualização e exclusão. As informações registradas incluem o usuário que realizou a operação, o momento em que ocorreu e o tipo de ação executada.

Praticando.

Lista os nomes de todos os usuários (roles com privilégio de login) existentes no banco de dados PostgreSQL. A consulta retorna a coluna usename, que contém os nomes dos usuários registrados no sistema.

            SELECT usename FROM pg_catalog.pg_user;
  • pg_catalog.pg_user:
    • É uma visão do sistema (system view) do PostgreSQL que armazena informações sobre usuários (ou "roles" que podem fazer login).
    • Está localizada no schema pg_catalog, que contém tabelas e visões internas do PostgreSQL.
  • Coluna usename:
    • Representa o nome do usuário (equivalente ao "username" no contexto de autenticação).

Use o comando CREATE ROLE para criar cada papel.

            -- Papel do diretor (com permissão de login)
            CREATE ROLE diretor WITH LOGIN PASSWORD 'diretor';

            -- Papel do monitor (sem login, apenas para agrupar permissões)
            CREATE ROLE monitor NOLOGIN;

Permissão de leitura (SELECT) para o usuário/role assistente em todas as tabelas existentes no esquema (schema) public do banco de dados.

            GRANT SELECT ON ALL TABLES IN SCHEMA public TO assistente;

Dando aceso a tabela 'clientes'

            GRANT SELECT ON clientes TO assistente;

O papel do diretor é ser assistente

            GRANT assistente TO diretor;

Verifica o papel do diretor

            SELECT 
            roleid::regrole AS papel,
            member::regrole AS membro,
            admin_option AS admin
            FROM pg_catalog.pg_auth_members
            WHERE member = 'diretor'::regrole;

            -- Saída
            "role_name"	    "membro"	"admin"
            "assistente"    "diretor"	false
