Introdução.

  • O tratamento de exceções é um dos recursos mais importantes da programação Java que nos permite tratar os erros em tempo de execução causados por exceções.
  • Nesta aula, aprenderemos o que é uma exceção, seus tipos, classes de exceção e como lidar com exceções em Java com exemplos.
O que é uma Exceção.
  • Uma exceção é um evento indesejado que interrompe o fluxo normal do programa.
  • Quando ocorre uma exceção, a execução do programa é encerrada.
    • Nesses casos, recebemos uma mensagem de erro gerada pelo sistema.
    • O bom das exceções é que podem ser tratadas em Java.
    • Ao lidar com as exceções, podemos fornecer uma mensagem significativa ao usuário sobre o problema em vez de uma mensagem gerada pelo sistema, que pode não ser compreensível para o usuário
Diferença entre Erro e Exceção.
  • Os erros indicam que algo grave o suficiente deu errado, o aplicativo deve travar em vez de tentar lidar com o erro.
  • Exceções são eventos que ocorrem no código. Um programador pode lidar com tais condições e tomar as ações corretivas necessárias.
Por que ocorrem Exceções?
  • Pode haver vários motivos que podem fazer com que um programa lance uma exceção.
  • Há erros que podem ser detectados durante a compilação, por falha do programador
    • Exemplos:
      • Associar valores a variáveis de tipos diferentes
      • Invocar um método inexistente
      • Tentar acessar um campo com acesso restrito
      • Tentar acessar uma variável de instância em um método estático
  • Há erros que podem surgir durante a execução do programa.
  • Exemplos.
    • Extrapolar limites de um vetor.
    • Divisão por zero.
    • Tentar acessar um arquivo que não existe.
    • Tentar acessar um diretório que não há permissão.
  • O tratamento de exceções se refere aos erros em tempo de execução.
  • Sempre que um erro ocorre, uma exceção (objeto) é criada e lançada.
  • A exceção (objeto) encapsula as informações do erro.
  • Essa exceção deve ser capturada em algum momento.
    • Cascata de chamadas de métodos.
    • Bloco try-catch, try-catch-finally.
  • Toda vez que surge um erro na execução de um método, o método cria um objeto de exceção e passa para o sistema de runtime do java (lança a exceção).
  • A execução do programa "congela" naquele ponto e o runtime procura o trecho de código mais próximo que seja capaz de capturar uma exceção daquele tipo.
  • Se a busca chegar ao main e não encontrar quem capture a exceção, o programa termina.

Tipos de Exceções.

Há 2 tipos de exceções:
  • Checked: Todas as exceções, exceto Runtime Exceptions, são conhecidas como exceções verificadas, pois o compilador as verifica durante a compilação para ver se o programador as manipulou ou não. Se essas exceções não forem tratadas / declaradas no programa, você obterá um erro de compilação.
    • Exemplo: SQLException, IOException, ClassNotFoundException etc.
  • Unchecked: As exceções de tempo de execução também são conhecidas como exceções não verificadas. Essas exceções não são verificadas em tempo de compilação, então o compilador não verifica se o programador as manipulou ou não, mas é responsabilidade do programador lidar com essas exceções e fornecer uma saída segura.
    • Exemplo: Arithmetic Exception, NullPointerException, ArrayIndexOutOfBoundsException etc.
  • Dentre as exceções que encaixam nos 2 tipos anteriores, temos:
    • Exception (checked).
    • RuntimeException (unchecked).
    • Error (unchecked).
  • São 3 classes em Java que derivam da classe Throwable.
Exception.
  • Precisam ser tratadas, pois são situações excepcionais em um programa que podem ser contornadas.
    • Abertura de um arquivo cujo nome foi informado errado pelo usuário.
    • Abertura do arquivo falha, gerando uma exceção que pode ser contornada pelo programador.
RuntimeException.
  • Representam erros internos na aplicação, mas que em geral não são tratáveis pelo programador.
    • Erros na lógica de programação.
    • Uso incorreto da API Java.
  • Por algum motivo, o programa lê o nome de um arquivo do usuário mas passa null para o construtor do arquivo.
  • O código precisa ser corrigido, embora a exceção gerada possa ser capturada pelo desenvolvedor.
Error.
  • Representam erros externos à aplicação, que não são contornáveis pelo programador.
    • Falha na leitura de um arquivo por um problema de hardware.
  • Embora a aplicação possa capturar este erro se quiser notificar o usuário, não é obrigatório.
    • Neste caso, o Java vai imprimir uma mensagem de erro e terminar o programa.
