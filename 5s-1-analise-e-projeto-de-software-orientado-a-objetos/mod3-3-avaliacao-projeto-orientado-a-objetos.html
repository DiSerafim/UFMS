Pergunta 1

Uma das desvantagens do padrão Controlador é que, se mal projetado, pode ter baixa coesão e tratar muitas áreas de responsabilidade.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

O padrão Controlador no GRASP tem como principal função coordenar operações do sistema (ex: em uma camada de serviços ou handlers), mas se mal aplicado, pode cair em armadilhas de design:

  1. Baixa Coesão:
    • Um controlador que gerencia múltiplas responsabilidades (ex: PedidoController que processa pagamentos, atualiza estoque e envia e-mails) viola o princípio da alta coesão.
    • Isso dificulta a manutenção e testes.
  2. Acoplamento Excessivo:
    • O controlador pode acabar centralizando demais a lógica, tornando-se um "God Object" (classe que faz tudo).

Pergunta 3

No contexto de GRASP, o que significa quem deveria ser "Criador"?

  • a. Uma interface de usuário especializada.
  • b. Uma classe que conhece as informações necessárias para inicializar uma instância de uma classe.
  • c. Um padrão que diminui o acoplamento entre classes.
  • d. Uma classe que armazena todas as informações do sistema.
  • e. Um método que é especialista em processamento de dados.
Resposta: b. ✅

📌 Explicação:

  • O padrão Criador (Creator) no GRASP define que a responsabilidade de criar instâncias de uma classe deve ser atribuída à classe que:
    • Contém os dados necessários para a criação OU
    • Agrega a instância a ser criada OU
    • Usa diretamente a instância OU
    • Registra a instância em seu sistema

Pergunta 4

Qual das seguintes opções é uma responsabilidade atribuída ao padrão Controlador?

  • a. Tratar eventos de sistema.
  • b. Gerenciar a interface do usuário diretamente.
  • c. Armazenar dados de configuração.
  • d. Sincronizar dados entre módulos.
  • e. Criar instâncias de objetos.
Resposta: a. ✅

📌 Explicação:

  • O padrão Controlador (Controller) no GRASP tem como principal responsabilidade:
    • Receber e tratar eventos do sistema (ex: ações do usuário, requisições HTTP, mensagens).
    • Coordenar a lógica de aplicação, delegando tarefas específicas a outras classes (como serviços ou especialistas).

Pergunta 5

O que são “responsabilidades” em um projeto orientado a objetos?

  • a. Apenas os atributos de uma classe.
  • b. Regras de negócio externas ao sistema.
  • c. Contratos ou obrigações de um tipo ou classe.
  • d. Métodos que os objetos não podem implementar.
  • e. Funções de interface de usuário.
Resposta: c. ✅

📌 Explicação:

  • Em projetos orientados a objetos, "responsabilidades" referem-se às tarefas, comportamentos ou obrigações que uma classe ou objeto deve cumprir para colaborar com o sistema. Isso inclui:
    • O que uma classe sabe (seus atributos e estados).
    • O que uma classe faz (seus métodos e operações).

Pergunta 6

O padrão Baixo Acoplamento favorece a reusabilidade do código ao reduzir a dependência entre as classes.

Escolha uma opção: Verdadeiro, Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • O padrão Baixo Acoplamento (Low Coupling) favorece a reusabilidade do código porque reduz as dependências entre as classes. Quando as classes são menos dependentes umas das outras, elas se tornam mais modulares e fáceis de reutilizar em diferentes contextos, sem a necessidade de modificar várias partes do código. Isso também facilita a manutenção e a escalabilidade do sistema.

Pergunta 7

Qual é a principal característica de uma classe com alta coesão?

  • a. Não possuir métodos estáticos.
  • b. Possuir muitos métodos não relacionados.
  • c. Ter funcionalidades altamente relacionadas.
  • d. Depender de muitas outras classes.
  • e. Ser responsável por várias tarefas diferentes.
Resposta: c. ✅

📌 Explicação:

  • Alta coesão significa que uma classe tem uma única responsabilidade bem definida e que todos os seus métodos e atributos estão fortemente relacionados a esse propósito. Isso torna a classe mais focada, fácil de entender, manter e reutilizar.

Pergunta 9

Os padrões GRASP (General Responsibility Assignment Software Patterns) incluem guias práticos para a tomada de decisões na atribuição de responsabilidades e alocação de métodos.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • Os padrões GRASP (General Responsibility Assignment Software Patterns) são justamente um conjunto de princípios que ajudam na tomada de decisões sobre atribuição de responsabilidades em projetos orientados a objetos. Eles fornecem guias práticos para:
    • Definir quais classes devem ser responsáveis por determinadas operações.
    • Alocar métodos de forma coesa e com baixo acoplamento.
    • Resolver problemas comuns de design, como quem deve criar um objeto (Creator), como controlar o acesso a recursos (Controller), entre outros.
  • Exemplos de Padrões GRASP:
    • Expert (Especialista) → Atribuir responsabilidades à classe com mais informação para cumpri-las.
    • Creator (Criador) → Definir qual classe deve instanciar outra.
    • Controller (Controlador) → Centralizar a gestão de fluxo do sistema.

Pergunta 10

Qual é a principal vantagem do padrão Baixo Acoplamento?

  • a. Facilita a substituição futura da interface com o usuário.
  • b. Aumenta o número de métodos em uma classe.
  • c. Aumenta a coesão das classes.
  • d. Reduz a dependência entre classes.
  • e. Diminui a quantidade de atributos nas classes.
Resposta: d. ✅

📌 Explicação:

  • O Baixo Acoplamento tem como objetivo minimizar as dependências entre classes, o que traz benefícios como:
    • Facilidade de manutenção: Mudanças em uma classe afetam menos outras partes do sistema.
    • Reusabilidade: Classes menos dependentes podem ser reaproveitadas em outros contextos.
    • Flexibilidade: Substituição ou modificação de componentes sem impactar o sistema como um todo.
