Modelagem como Técnica de Análise.

  • Um software de boa qualidade só pode ser obtido se o desenvolvimento for direcionado em conformidade aos requisitos;
  • O bom entendimento dos requisitos é a base para a Análise e o Projeto de Software;
  • Descobrir e explicitar informações para identificar o problema;
  • Modelar o mundo real para torná-lo mais compreensível;
  • Durante a análise, a ênfase está em abstrair as entidades do domínio relevantes para o sistema que se pretende construir.
  • Um modelo é uma abstração de alguma coisa, cujo propósito é permitir que se conheça essa coisa antes de construí-la;
  • Um modelo omite os detalhes não essenciais e, portanto, sua manipulação é mais fácil do que a da entidade original.

Princípios de Modelagem para Análise.

  • A abstração é uma fundamental capacidade humana que nos permite lidar com elementos complexos;
  • Engenheiros, artistas e artesãos constroem modelos há milhares de anos para testar projetos antes de executá-los;
  • No desenvolvimento de sistemas, “abstrair” significa concentrar-se no que um objeto é e faz, antes de decidir como ele deve ser implementado.

Análise de Domínio.

  • Para compreender o objeto é preciso entender e identificar o contexto que o envolve;
  • Essa compreensão ajuda a definir o objeto e os demais relacionados em um determinado contexto → Análise de Domínio;
  • O domínio de informação de um problema precisa ser representado de maneira clara;
  • Ex. Diagramas UML, Mapa Mental, Plantas.
  • As funções e operações a serem desempenhadas pelo Software devem ser bem definidas, isso é representado na orientação a objetos como a responsabilidade dos objetos → Métodos.
  • O comportamento reativo do Software, ou seja, a maneira como ele responde a eventos externos específicos, precisa ser representado;
  • Na construção de um modelo, não se deve procurar a verdade absoluta, mas sim a adequação a algum propósito. Não há um único modelo “correto” de uma situação, apenas modelos adequados e inadequados.
  • O uso da abstração durante a análise significa:
    • lidar apenas com conceitos do domínio da aplicação;
    • não ter que tomar decisões sobre o projeto e a implementação antes do problema ser compreendido.

Objetivos da modelagem.

  • Os modelos servem para diversos objetivos:
    • Entender o que está sendo construído:
      • obter visualização do delineamento das ideias;
    • Melhorar comunicação entre os membros da equipe e com os clientes;
    • Testar uma entidade antes de lhe dar forma;
    • Reduzir a complexidade.

A prática da modelagem.

  • Modelos de Análise:
    • Modelagem Estática:
      • Identificação de Classes que executam os casos de uso identificados;
      • Identificação dos relacionamentos entre as classes encontradas.

Os princípios da modelagem.

  1. O domínio de informação de um problema precisa ser representado e entendido;
  2. As funções a serem desenvolvidas pelo software devem ser definidas;
  3. O comportamento do software (como consequência de eventos externos) precisa ser representado;
  4. A tarefa de análise deve começar na informação essencial e partir para informações mais detalhadas.
