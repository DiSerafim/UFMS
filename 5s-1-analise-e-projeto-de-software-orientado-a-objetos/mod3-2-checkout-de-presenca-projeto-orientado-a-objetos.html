Materiais

Neste módulo, você teve a oportunidade de explorar o Projeto Orientado a Objetos: desenho de projeto e padrões gerais de atribuição de responsabilidades (GRASP). Agora, é hora de aplicar esses conceitos por meio da elaboração de um Diagrama de Classes da UML para o sistema proposto nas atividades dos dois módulos anteriores.

Contextualização da Atividade:

  • A atividade proposta consiste na criação de um Diagrama de Classes da UML que represente o sistema proposto nas atividades dos módulos anteriores. Este diagrama deve oferecer uma visão de implementação do sistema, evoluindo o modelo conceitual desenvolvido anteriormente e incluindo as responsabilidades de cada classe, seguindo os padrões GRASP.

Conteúdo

Passos para realização da atividade:

  1. Definição do Escopo do Diagrama de Classes: Identifique o escopo do sistema a ser representado no diagrama, considerando as funcionalidades e entidades principais.
  2. Desenho do Diagrama de Classes: Utilizando uma ferramenta UML de sua escolha, crie o Diagrama de Classes que represente de forma completa o sistema proposto. Certifique-se de incluir todas as classes relevantes, seus atributos e relacionamentos, lembre-se de usar como base inicial seu modelo conceitual proposto no módulo anterior.
  3. A atribuição de Responsabilidades, ou seja, a inserção dos métodos das classes devem ser realizadas, utilizando os Padrões GRASP. Considere principalmente o Especialista na Informação, Alta Coesão e Baixo Acoplamento.
  4. Validação e Evolução do Modelo Conceitual: Revise o diagrama criado, garantindo que ele ofereça uma visão clara e precisa do sistema proposto. Certifique-se de que o modelo evolui adequadamente a partir do modelo conceitual desenvolvido anteriormente.
  5. Exportação para PDF: Após a conclusão do Diagrama de Classes, exporte-o para um arquivo PDF, assegurando que ele esteja legível e bem formatado.

Resolução

Modelo conceitual UML - Sistema de App Delivery.
  1. Definição do Escopo do Diagrama de Classes: Identifique o escopo do sistema a ser representado no diagrama, considerando as funcionalidades e entidades principais.
    • Este modelo foi desenvolvido para representar um sistema de entrega online, com funcionalidades de gerenciamento de usuários (clientes, vendedores, e admins), controle de pedidos e carrinho de compras e status de pedidos. Utiliza uma abordagem orientada a objetos com o auxílio da UML, visando maior clareza e padronização na modelagem de sistemas.
      • Gestão de usuários (clientes, vendedores e administrador).
      • Processo de compra (produtos, pedidos, checkout).
      • Acompanhamento de pedidos.
      • Comunicação em tempo real.
  2. Desenho do Diagrama de Classes: Utilizando uma ferramenta UML de sua escolha, crie o Diagrama de Classes que represente de forma completa o sistema proposto. Certifique-se de incluir todas as classes relevantes, seus atributos e relacionamentos, lembre-se de usar como base inicial seu modelo conceitual proposto no módulo anterior.
    • Classe User (Armazena os dados do usuário):
      • id: Integer (PK).
      • name: String.
      • email: String.
      • password: String (hash md5).
      • role: Enum[customer, seller, admin].
      • createdAt: DateTime.
      • updatedAt: DateTime.
    • Subclasse Customer (Representa o cliente):
      • deliveryAddress: String.
    • Subclasse Seller (Representa o vendedor):
      • storeId: Integer (FK).
    • Class Product (Representa os produtos a venda):
      • id: Integer (PK).
      • name: String.
      • price: Decimal.
      • imageUrl: String.
      • stock: Integer.
      • category: String.
    • Classe Order (Representa os pedidos feitos pelos clientes):
      • id: Integer (PK).
      • customerId: Integer (FK).
      • sellerId: Integer (FK).
      • totalPrice: Decimal.
      • deliveryAddress: String.
      • status: Enum [pending, preparing, in_transit, delivered].
      • createdAt: DateTime.
      • updatedAt: DateTime.
    • Classe OrderItem (Armazena informação sobre um pedido):
      • id: Integer (PK).
      • orderId: Integer (FK).
      • productId: Integer (FK).
      • quantity: Integer.
      • unitPrice: Decimal.
    • Classe ShoppingCart (Representa as compras de um cliente):
      • id: Integer (PK).
      • customerId: Integer (FK).
      • createdAt: DateTime.
    • Classe CartItem (Armazena os items adicionados por um cliente):
      • id: Integer(PK).
      • cartId: Integer(FK).
      • productId: Integer(FK).
      • quantity: Integer.
  3. A atribuição de Responsabilidades, ou seja, a inserção dos métodos das classes devem ser realizadas, utilizando os Padrões GRASP. Considere principalmente o Especialista na Informação, Alta Coesão e Baixo Acoplamento.
    • Relacionamentos:
      • User é a classe base de Customer e Seller.
      • Customer (1:N) Order | "Um para muitos".
      • Seller (1:N) Order | "Um para muitos".
      • Order (1:N) OrderItem | "Um para muitos".
      • Product (1:N) OrderItem | "Um para muitos".
      • Customer (1:1) ShoppingCart | "Um para um".
      • ShoppingCart (1:N) CartItem | "Um para muitos".
      • Product (1:N) CartItem | "Um para muitos".
  4. Validação e Evolução do Modelo Conceitual: Revise o diagrama criado, garantindo que ele ofereça uma visão clara e precisa do sistema proposto. Certifique-se de que o modelo evolui adequadamente a partir do modelo conceitual desenvolvido anteriormente.
    1. O modelo tem uma organização clara das classes e heranças.
    2. Relacionamentos definidos e com cardinalidade.
    3. Aplica o princípio de orientação a objetos.
      • Encapsulamento (atributos organizados por classe), Herança ('User' como superclasse), Polimorfismo (possível uso futuro para tratamento uniforme de diferentes 'roles').
