Materiais

Neste fórum, vamos explorar o design de software orientado a objetos e os padrões gerais de atribuição de responsabilidades (GRASP). Esses padrões são fundamentais para a criação de sistemas robustos e flexíveis e é importante compreendê-los para projetar soluções eficientes e de fácil manutenção.

Sua tarefa é escolher um dos padrões GRASP, como Criador, Controlador, Especialista da Informação ou outros, e discutir sua importância e aplicação no Projeto (design) de software. Busque e compartilhe exemplos práticos de como esse padrão é utilizado para atribuir responsabilidades às classes e promover um design coeso e flexível.

Conteúdo

Questões:

Adicionalmente, proponha uma questão que estimule a reflexão sobre como a aplicação dos padrões GRASP pode contribuir para a melhoria da qualidade e da eficiência dos sistemas de software.

  1. Qual padrão GRASP você considera mais relevante para o design de software?
  2. Como ele pode ser aplicado para melhorar a qualidade dos sistemas?

Resolução.

Ex.: Especialista da Informação.

1 - Qual padrão GRASP você considera mais relevante para o design de software?

  • O especialista, pois determina que uma classe deve ser responsável por uma operação e se ela possui os dados necessários para realizar a operação.
    • Baseia outros padrões GRASP, como criador ou controlador.
    • Reflete o princípio de encapsulamento da POO, mantendo dados e comportamentos relacionados juntos.
    • Reduz a complexidade ao atribuir responsabilidades de forma intuitiva, quem tem os dados executa a ação.

2 - Como ele pode ser aplicado para melhorar a qualidade dos sistemas?

  • A aplicação do especialista, melhora a qualidade.

Ex.:

            class Cart {
                constructor () {
                    this.items = []; // { product, price, quantity }
                };

                // O carrinho é o especialista pois tem os dados necessários
                calculateTotal () {
                    return this.itens.reduce(
                        (total, item) => total + (item.price * item.quantity), 0
                    );
                };
            };
  • Benefícios:
    • Coesão: A lógica de cálculo fica dentro da classe que possui os dados (items).
    • Baixo acoplamento: Nenhuma classe externa precisa acessar items diretamente.
    • Manutenção simplificada: Alterações, ex.: Adicionar descontos, são locais.

Reflexão:

  • O especialista pode prevenir vazamento de detalhes internos (ex.: export arrays como items ou objetos internos).
  • O especialista promove uma organização clara, dados e comportamentos ficam juntos.
  • Redux os bugs, minimiza o acesso indevido a estados internos.
