Pergunta 1

Os diagramas de interação são usados para modelar a estrutura estática de um sistema.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Falso. ✅

📌 Explicação:

Os diagramas de interação não são usados para modelar a estrutura estática de um sistema. Eles fazem parte da UML (Unified Modeling Language) e são utilizados para representar o comportamento dinâmico e as interações entre os objetos/components de um sistema.

Detalhes importantes:

    1. Diagramas de Estrutura Estática (que modelam a estrutura):
      • Diagrama de Classes
      • Diagrama de Objetos
      • Diagrama de Componentes
      • Diagrama de Implantação
    2. Diagramas de Interação (que modelam o comportamento dinâmico):
      • Diagrama de Sequência (mostra interações temporais)
      • Diagrama de Comunicação (ênfase nos relacionamentos)
      • Diagrama de Tempo (foco em restrições temporais)
      • Diagrama de Visão Geral de Interação
    3. Erro comum:
      • Diagramas de estrutura mostram "o que" existe no sistema
      • Diagramas de interação mostram "como" esses elementos se comunicam e interagem durante a execução

Pergunta 2

Qual diagrama UML descreve o comportamento dinâmico de um sistema?

  • a. Diagrama de Objetos.
  • b. Diagrama de Componentes.
  • c. Diagrama de Atividades.
  • d. Diagrama de Pacotes.
  • e. Diagrama de Estrutura Composta.
Resposta: c. ✅

📌 Explicação:

  • O Diagrama de Atividades é um tipo de diagrama comportamental da UML que descreve o fluxo dinâmico de um sistema, representando a sequência de ações, decisões e paralelismos em um processo.

Pergunta 3

Qual é o uso mais recorrente dos diagramas UML no desenvolvimento?

  • a. Representar a interface gráfica.
  • b. Definir requisitos de hardware.
  • c. Detalhar a lógica de programação.
  • d. Descrever dados de entrada e saída.
  • e. Documentar a estrutura e o comportamento do sistema.
Resposta: e. ✅

📌 Explicação:

  • Os diagramas UML (Unified Modeling Language) são amplamente utilizados para documentar e visualizar tanto a estrutura estática (como classes, componentes e relações) quanto o comportamento dinâmico (fluxos, interações e estados) de um sistema de software.

Pergunta 4

Qual é a finalidade principal da UML?

  • a. Criar uma notação padronizada para documentação de software.
  • b. Implementar soluções de rede.
  • c. Substituir todas as outras linguagens de programação.
  • d. Desenvolver jogos.
  • e. Fornecer um processo de desenvolvimento.
Resposta: a. ✅

📌 Explicação:

  • A UML (Unified Modeling Language) foi criada principalmente para oferecer uma linguagem visual padronizada que permite:
    1. Documentar sistemas de software de forma clara e consistente.
    2. Modelar estruturas (como classes, componentes) e comportamentos (fluxos, interações).
    3. Facilitar a comunicação entre desenvolvedores, analistas e stakeholders.

Pergunta 5

Qual é uma prática importante na modelagem de análise?

  • a. Identificar classes que executam casos de uso.
  • b. Focar exclusivamente em métodos.
  • c. Concentração em fluxos de dados.
  • d. Ignorar relacionamentos entre classes.
  • e. Evitar abstração de conceitos.
Resposta: a. ✅

📌 Explicação:

  • Na modelagem de análise orientada a objetos, uma das práticas mais importantes é identificar as classes que colaboram para realizar os casos de uso do sistema. Isso porque:
    1. Alinhamento com requisitos: Os casos de uso representam as funcionalidades que o sistema deve oferecer, então as classes identificadas devem dar suporte a essas funcionalidades.
    2. Abordagem centrada no domínio: Foca primeiro nos conceitos do domínio do problema antes de pensar em implementação.
    3. Base para o design: Essas classes de análise serão refinadas posteriormente no design.

Pergunta 6

Na análise de domínio, qual é o foco principal?

  • a. Testes unitários.
  • b. Identificação do contexto envolvente.
  • c. Implementação de soluções.
  • d. Definição de algoritmos.
  • e. Detalhamento de interfaces.
Resposta: b. ✅

📌 Explicação:

  • A análise de domínio é uma etapa crucial no desenvolvimento de software orientado a objetos, e seu foco principal está em:
    1. Compreender o domínio do problema:
      • Identificar os conceitos, regras de negócio e processos relevantes.
      • Mapear os principais atores, entidades e relacionamentos do mundo real que o sistema deve representar.
    2. Definir o contexto do sistema:
      • Delimitar o escopo do que será modelado.
      • Estabelecer os limites entre o sistema e o ambiente externo (atores, sistemas legados, etc.).
    3. Criar um modelo conceitual:
      • Representar as entidades do domínio e como elas se relacionam (ex: Diagrama de Classes de Domínio).
      • Priorizar a clareza do domínio em vez de detalhes técnicos ou de implementação.

Pergunta 7

Associe os princípios da modelagem aos seus significados:

                Como o software responde a eventos externos (...).
                Lidar apenas com conceitos relevantes ao contexto (...).

Opções: Princípio 1: Abstrair o domínio da aplicação, Princípio 2: Entender o comportamento reativo do software.

Resposta: ✅ 
                Como o software responde a eventos externos Princípio 2: Entender o comportamento reativo do software.
                Lidar apenas com conceitos relevantes ao contexto Princípio 1: Abstrair o domínio da aplicação.

📌 Explicação:

  1. Princípio: Comportamento
    • Significado: Este princípio foca na modelagem das respostas dinâmicas do sistema a estímulos externos, representado por diagramas como:
      • Diagrama de Estados (transições entre estados)
      • Diagrama de Sequência (interações em resposta a eventos)
  2. Princípio: Abstração
    • Significado: Envolve selecionar apenas os elementos essenciais do domínio, ignorando detalhes irrelevantes. Isso é crítico em:
      • Diagrama de Classes de Domínio (mostra apenas conceitos do negócio)
      • Casos de Uso (foca nas funcionalidades visíveis ao usuário)

Pergunta 8

A análise de domínio foca em compreender o contexto e os objetos relacionados a um problema específico.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

📌 Explicação:

  • A análise de domínio tem como objetivo principal compreender o contexto do problema e identificar os objetos/conceitos relevantes do mundo real que o sistema de software deve representar. Isso inclui:
    1. Contexto:
      • Limites do sistema (o que está dentro e fora do escopo).
      • Interações com atores externos (usuários, outros sistemas).
    2. Objetos do domínio:
      • Entidades principais (ex: em um sistema de transporte: Ônibus, Passageiro, Rota).
      • Regras de negócio (ex: como calcular o tempo de chegada de um ônibus).
    3. Abstração:
      • Focar apenas nos conceitos essenciais para o problema, ignorando detalhes irrelevantes.

Pergunta 9

Quais diagramas são considerados estruturais na UML?

  • a. Diagramas de Classes e Componentes.
  • b. Diagramas de Atividades e Máquina de Estados.
  • c. Diagramas de Tempo e Comunicação.
  • d. Diagramas de Sequência e Comunicação.
  • e. Diagramas de Casos de Uso e Atividades.
Resposta: a. ✅

📌 Explicação:

  • Os diagramas estruturais da UML representam a organização estática do sistema, focando em elementos permanentes e seus relacionamentos. Os principais são:
    1. Diagrama de Classes:
      • Mostra classes, atributos, métodos e relacionamentos (herança, associações).
      • Exemplo: Classe Ônibus com atributos como placa e rotaAtual.
    2. Diagrama de Componentes:
      • Ilustra módulos do sistema (componentes) e suas dependências.
      • Exemplo: Componentes RastreamentoGPS e ServiçoDeNotificações.
    3. Outros diagramas estruturais:
      • Diagrama de Objetos: Instâncias específicas de classes em um momento.
      • Diagrama de Implantação: Distribuição física em hardware.
      • Diagrama de Pacotes: Organização de elementos em grupos lógicos.

Exemplo em Código (python): 

                class Pessoa:  # Classe
                def __init__(self, nome, idade):
                self.nome = nome  # Atributo
                self.idade = idade  # Atributo
                
                def apresentar(self):  # Método
                print(f"Olá, sou {self.nome}!")
                # Objetos (instâncias):
                pessoa1 = Pessoa("Ana", 30) # Objeto 1
                pessoa2 = Pessoa("João", 25) # Objeto 2

Pergunta 10

Associe cada diagrama UML à sua finalidade:

                Representar a estrutura de classes e seus relacionamentos (...).
                Mostrar a sequência temporal das interações entre objetos (...).

Opções: Diagrama de Classes, Diagrama de Sequência.

Resposta: ✅ 
                Representar a estrutura de classes e seus relacionamentos Diagrama de Classes.
                Mostrar a sequência temporal das interações entre objetos Diagrama de Sequência.

📌 Explicação:

  1. Diagrama de Classes
    • Finalidade: Representar a estrutura de classes, seus atributos, métodos e relacionamentos (herança, associações, dependências).
    • Exemplo:
      •                         classDiagram
                            class Passageiro {
                                +id: int
                                +nome: string
                                +reservarViagem()
                            }
                            class Onibus {
                                +placa: string
                                +capacidade: int
                            }
                            Passageiro "1" --> "n" Onibus
  2. Diagrama de Sequência
    • Finalidade: Mostrar a ordem temporal das interações entre objetos em um cenário específico (troca de mensagens).
    • Exemplo:
      •                             sequenceDiagram
                                Passageiro->>Sistema: Solicitar reserva
                                Sistema->>Onibus: Verificar disponibilidade
                                Onibus-->>Sistema: Confirmar
                                Sistema-->>Passageiro: Reserva concluída
