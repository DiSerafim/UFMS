Pergunta 1

Os métodos ágeis priorizam:

  • a. Documentação extensa e detalhada.
  • b. Adaptação a mudanças de escopo.
  • c. Uso de metodologias rígidas.
  • d. Entregas anuais.
  • e. Reuniões formais e frequentes.
Resposta: b. ✅

Explicação:

  • Os métodos ágeis (como Scrum, XP, Kanban) têm como princípios fundamentais:
    1. Flexibilidade para aceitar mudanças de requisitos (priorizando a adaptação sobre o planejamento rígido).
    2. Entregas incrementais e frequentes (semanais/mensais, não anuais).
    3. Valorizar indivíduos e interações mais que processos burocráticos (reuniões são objetivas, como stand-ups diárias).
    4. Documentação suficiente, mas não extensa (o foco é software funcionando).

Pergunta 2

Herança permite que uma classe derive características de outra classe.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

Explicação:

  • Herança é um dos pilares da Orientação a Objetos (OO) que permite que uma classe (chamada subclasse ou classe filha) herde atributos e métodos de outra classe (chamada superclasse ou classe pai). Isso promove:
    • Reutilização de código (evita repetição).
    • Hierarquia entre classes (ex.: Animal → Cachorro).

Pergunta 3

O conceito de classe em orientação a objetos representa:

  • a. Um método específico de um objeto.
  • b. Um código sem atributos.
  • c. Uma única instância de um objeto.
  • d. Um grupo de objetos que compartilham estrutura e comportamento.
  • e. Uma variável global.
Resposta: d. ✅

Explicação:

  • Em Orientação a Objetos, uma classe é:
    1. Modelo/Projeto (Blueprint) que define:
      • Atributos (dados)
      • Métodos (comportamentos)
      • Que serão compartilhados por todos os objetos criados a partir dela
    2. Exemplo Prático (java):
      3.                         // Classe Pessoa (modelo)
                        class Pessoa {
                            // Atributos (estrutura)
                            String nome;
                            int idade;

                            // Métodos (comportamento)
                            void falar() {
                                System.out.println("Olá, meu nome é " + nome);
                            }
                        }
    3. Relação Classe-Objeto:
      • Classe = Molde (ex.: "Pessoa")
      • Objeto = Instância concreta (ex.: Pessoa pessoa1 = new Pessoa();)

Pergunta 4

Qual é a principal função dos métodos em um objeto?

  • a. Realizar operações que alteram o estado do objeto.
  • b. Definir as características fixas de um objeto.
  • c. Impedir a comunicação entre objetos.
  • d. Armazenar dados sem modificações.
  • e. Servir apenas como placeholders.
Resposta: a. ✅

Explicação:

  • Métodos em Orientação a Objetos são as ações/comportamentos de um objeto, com as seguintes funções principais:
    1. Modificar o estado interno (atributos) do objeto (java):
      2.                         class ContaBancaria {
                            private double saldo; // estado interno
                            
                            // MÉTODO que altera o estado
                            void depositar(double valor) {
                                this.saldo += valor; // altera o atributo 'saldo'
                            }
                        }
    2. Realizar operações baseadas no estado atual (java):
      3.                         double verificarSaldo() {
                            return this.saldo; // consulta sem modificar
                        }
    3. Encapsular lógica (ocultar detalhes de implementação) (java):
      4.                         void transferir(Conta destino, double valor) {
                            if (this.saldo >= valor) {
                                this.sacar(valor);
                                destino.depositar(valor);
                            }
                        }

Pergunta 5

Qual é um dos principais desafios do Desenvolvimento Orientado a Objetos?

  • a. Baixo custo de desenvolvimento.
  • b. Complexidade inicial elevada.
  • c. Facilidade em integração.
  • d. Simplicidade no design.
  • e. Resiliência a mudanças.
Resposta: b. ✅

Explicação:

  • O Desenvolvimento Orientado a Objetos (OOD) apresenta como um de seus principais desafios a complexidade inicial elevada, devido a:
    1. Custo de abstração inicial:
      • Necessidade de modelar classes, hierarquias e relações antes da implementação
      • Exemplo: Projetar uma hierarquia de classes para um sistema bancário requer análise profunda de entidades (Conta, Cliente, Transação etc.)
    2. Curva de aprendizado:
      • Domínio de conceitos como herança, polimorfismo e encapsulamento
      • Padrões de projeto (Design Patterns) acrescentam outra camada de complexidade
    3. Sobredesign comum:
      • Tendência a criar estruturas excessivamente complexas para cenários simples
      • Exemplo: Usar herança múltipla quando uma composição seria suficiente

Pergunta 7

Qual das opções é uma vantagem da abordagem orientada a objetos em relação à manutenção?

  • a. Maior dependência de linguagens específicas.
  • b. Requisitos mais rígidos para alteração.
  • c. Menor modularidade.
  • d. Facilitação da manutenção através da modularização das classes.
  • e. Dificuldade em encontrar bugs.

Resposta: d. ✅

Explicação:

  • A Orientação a Objetos (OO) oferece vantagens significativas para a manutenção de software, principalmente devido à:
    1. Modularização:
      • Classes encapsulam comportamentos e estados relacionados
      • Exemplo: Alterar a classe CalculadoraImposto não afeta RelatorioFinanceiro
    2. Princípios que facilitam a manutenção:
      • Encapsulamento: Mudanças internas numa classe não afetam outras (java)
        •                             public class ContaBancaria {
                                private double saldo; // Alterar tipo para BigDecimal afeta só esta classe
                                public void depositar(double valor) { ... }
                            }
      • Baixo acoplamento: Classes se comunicam através de interfaces bem definidas
      • Alta coesão: Cada classe tem responsabilidade única
    3. Benefícios práticos:
      • Correção de bugs em classes específicas sem impactar o sistema todo
      • Adição de funcionalidades via novas classes (Open/Closed Principle)
      • Melhor legibilidade e organização do código

Pergunta 8

Como a herança é utilizada em orientação a objetos?

  • a. Para eliminar redundâncias entre classes.
  • b. Para descrever relações estáticas entre classes.
  • c. Para isolar funcionalidades específicas.
  • d. Para criar uma nova classe a partir de uma existente.
  • e. Para definir interfaces complexas.
Resposta: d. ✅

Explicação:

  • A herança em Orientação a Objetos é um mecanismo que permite:
    1. Criar subclasses baseadas em classes existentes (superclasses) (java):
      2.                         class Veiculo {  // Superclasse
                            void mover() { System.out.println("Movendo"); }
                        }
                        class Carro extends Veiculo {  // Subclasse
                            void acelerar() { System.out.println("Acelerando"); }
                        }
    2. Propósitos principais:
      • Reutilização de código: A subclasse herda atributos e métodos da superclasse
      • Extensão de funcionalidades: A subclasse pode adicionar novos comportamentos
      • Especialização: Refinar o comportamento da superclasse (via @Override)

      • Classe = Receita de bolo (molde)

Pergunta 10

Encapsulamento significa que todos os atributos de um objeto são públicos.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Falso. ✅

Explicação:

  • O encapsulamento em Orientação a Objetos é justamente o princípio que:
    1. Protege os atributos de um objeto, tornando-os privados (ou protegidos) na maioria dos casos (java):
      2.                         public class ContaBancaria {
                            private double saldo; // Atributo PRIVADO (não público)
                            
                            public void depositar(double valor) { // Método público para acesso controlado
                                if (valor > 0) {
                                    this.saldo += valor;
                                }
                            }
                        }
    2. Expõe apenas métodos públicos para interação segura:
      • Getters (acesso) e setters (modificação) controlados.
      • Exemplo: getSaldo() pode ter regras de auditoria antes de retornar o valor.
    3. Objetivos do encapsulamento:
      • Evitar acesso direto e inconsistente ao estado interno.
      • Permitir validações/alterações centralizadas (ex.: não permitir saldo < 0).
      • Reduzir acoplamento entre classes.
