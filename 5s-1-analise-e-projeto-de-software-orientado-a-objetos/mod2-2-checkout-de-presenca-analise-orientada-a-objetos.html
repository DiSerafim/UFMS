Materiais

Neste módulo, você teve a oportunidade de aprofundar seus conhecimentos na Análise Orientada a Objetos: processos de análise e linguagem unificada. Agora, chegou o momento de aplicar esses conceitos de forma prática por meio de uma atividade de modelagem conceitual.

A análise orientada a objetos é uma abordagem fundamental no desenvolvimento de software, permitindo a compreensão e representação dos sistemas de forma mais eficiente e precisa. A linguagem unificada (UML) é uma ferramenta poderosa para expressar esses conceitos de forma visual e padronizada.

Conteúdo

Para esta atividade de checkout, convido você a criar um modelo conceitual, utilizando elementos da UML para representar os objetos do sistema proposto na atividade do módulo anterior. Seu modelo deve incluir classes, relacionamentos e atributos relevantes para a compreensão do sistema.

Passos para realização da atividade:

  1. Definição do Escopo do Modelo Conceitual: Estabeleça o escopo do modelo, identificando os principais objetos e entidades que fazem parte do sistema proposto na atividade do módulo anterior.
  2. Identificação das Classes e Atributos: Liste as classes que compõem o sistema e seus atributos correspondentes. Certifique-se de incluir todos os atributos para descrever completamente cada classe.
  3. Modelagem dos Relacionamentos: Desenhe os relacionamentos entre as classes, indicando a natureza e o tipo de associação entre elas. Considere a cardinalidade e a multiplicidade dos relacionamentos.
  4. Validação do Modelo: Revise o modelo conceitual criado, verificando se ele representa de forma precisa e clara os objetos e relacionamentos do sistema proposto.
  5. Exportação para PDF: Após a conclusão do modelo conceitual, exporte-o para um arquivo PDF, garantindo que ele esteja legível e bem formatado.

Resolução

Modelo conceitual UML para o Sistema de App Delivery.
  1. Definição do Escopo do Modelo Conceitual:
    • Este modelo foi desenvolvido para um sistema de delivery em um projeto da Trybe, com foco nas principais entidades e seus relacionamentos. Seu escopo inclui:
      • Gestão de usuários (clientes, vendedores e administrador).
      • Processo de compra (produtos, pedidos, checkout).
      • Acompanhamento de pedidos.
      • Comunicação em tempo real.
  2. Identificação das Classes e Atributos:
    • User:
      • id: Integer (PK).
      • name: String.
      • email: String.
      • password: String (hash md5).
      • role: Enum[customer, seller, admin].
      • createdAt: DateTime.
      • updatedAt: DateTime.
    • Customer:
      • DeliveryAddress: String.
    • Seller:
      • storeId: Integer (FK).
    • Product:
      • id: Integer (PK).
      • name: String.
      • price: Decimal.
      • imageUrl: String.
      • stock: Integer.
      • category: String.
    • Order:
      • id: Integer (PK).
      • customerId: Integer (FK).
      • sellerId: Integer (FK).
      • totalPrice: Decimal.
      • deliveryAddress: String.
      • status: Enum [pending, preparing, in_transit, delivered].
      • createdAt: DateTime.
      • updatedAt: DateTime.
    • OrderItem:
      • id: Integer (PK).
      • orderId: Integer (FK).
      • productId: Integer (FK).
      • quantity: Integer.
      • unitPrice: Decimal.
    • shoppingCart:
      • id: Integer (PK).
      • customerId: Integer (FK).
      • createdAt: DateTime.
    • CartItem:
      • id: Integer(PK).
      • cartId: Integer(FK).
      • productId: Integer(FK).
      • quantity: Integer.
  3. Modelagem dos Relacionamentos:
    • User (customer, seller, admin).
      • Todo usuário tem uma função específica.
    • Customer → Order (1:N).
      • Um cliente pode ter vários pedidos.
      • Um pedido pertence a um único cliente.
    • Seller → Order (1:N).
      • Um vendedor pode ter vários pedidos.
      • Um pedido é atendido por um único vendedor.
    • Order → OrderItem (1:N).
      • Um pedido contém vários itens.
      • Um item pertence a um único pedido.
    • Product → OrderItem (1:N).
      • Um produto pode aparecer em vários itens de pedido.
      • Um item de pedido referência um único produto.
    • Customer → ShoppingCart (1:1).
      • Um cliente tem um carrinho ativo.
      • Um carrinho pertence a um único cliente.
    • ShoppingCart → CartItem (1:N).
      • Um carrinho contém vários itens.
      • Um item pertence a um único carrinho.
    • Product → CartItem (1:N).
      • Um produto pode estar em vários carrinhos.
      • Um item do carrinho referência um único produto.
  4. Validação do Modelo:
    1. Este modelo representa um sistema de delivery.
    2. Mostra os relacionamentos essenciais.
    3. Mostra a cardinalidade entre as entidades.
    4. Inclui os atributos essenciais para cada classe.
    5. Segue o princípio de orientação a objetos.
      • Encapsulamento (atributos privados), Herança (especialização de User), Polimorfismo (tratamento uniforme de diferentes tipos de User).
