Materiais

Neste módulo, você estudou o Modelo MVC (Model-View-Controller), uma arquitetura amplamente utilizada no desenvolvimento de software, principalmente em desenvolvimento Web. Vamos explorar sua aplicação prática?

O Modelo MVC é uma abordagem que separa as preocupações de uma aplicação em três componentes: Modelo, Visão (View) e Controlador (Controller). Agora, convido você a discutir como essa abordagem pode ser aplicada eficazmente em projetos reais.

Conteúdo

O que fazer para participar do fórum:

  1. Descreva um projeto de software: Web, Sistema, App etc. (real ou fictício) em que você consideraria apropriada a aplicação do Modelo MVC.
  2. Explique como você dividiria as responsabilidades entre o Modelo, a Visão e o Controlador nesse projeto.

Questões para discussão:

  1. Quais são as vantagens de usar o Modelo MVC na organização de um projeto de desenvolvimento de software?
  2. Quais são os desafios comuns encontrados ao implementar o Modelo MVC?

Resolução.

Projeto: Pizzaria

Descrição:

Um site para uma pizzaria, onde os clientes possam fazer pedidos online, e a pizzaria pode acompanhar e gerenciar esses pedido em tempo real. Um sistema com três áreas: Um portal para os clientes, um painel de gerenciamento e uma área de relatório onde é possível ver o andamento dos pedidos.

Divisão MVC:
  • Model:
    • Ficaria responsável pela lógica e manipulação dos cados, como as entidades (pedido, cardápio, cliente e status do pedido) onde contem as informações do restaurante e métodos para gerenciar e atualizar.
    • Também é a parte que interage com o banco de dados o CRUD.
  • View:
    • Aqui será o front-end a parte de interface de usuário(UI), onde ficará visível para todos, exceto a parte de administração.
    • Exibe em tempo real os pedidos, altera o status, atualiza o menu.
  • Controller:
    • Aqui é a parte que ficará responsável por fazer a ponte entre o model e o view, como se fosse um garçon que faz a ligação entre o cliente e a cozinha. rsrs
    • o controller fica responsável por validar as informações, criar e ou atualizar um pedido
Vantagens MVC:
  • Separa as responsabilidades:
    • O MVC organiza as responsabilidades de maneira clara. Cada camada pode ser desenvolvida e mantida independentemente, reduzindo os erros.
  • Reutiliza código:
    • É possível reutilizar o model para diferentes views, como uma versão mobile ou web, sem alterar a lógica.
  • Manutenção e atualização fácil:
    • Em caso de ajustes, cada camada pode ser modificada independentemente, tornando o sistema flexível.
Desafios MVC:
  • Complexidade na integração:
    • a separação exige planejamento para que a comunicação entre as partes funcione de maneira eficiente.
  • Sobrecarga no controller:
    • Excesso de responsabilidades, tornando difícil manter o código.
  • Aprendizado:
    • A lógica é bem complicada, em teoria parece ser mais simples.
