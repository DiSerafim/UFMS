Pergunta 1

Qual é o principal objetivo dos web services?

  • a. Renderização de gráficos.
  • b. Processamento de texto.
  • c. Comunicação entre diferentes aplicações.
  • d. Interagir com bancos de dados.
  • e. Criação de jogos online.
Resposta: c. ✅

Resolução:

  • O principal objetivo dos web services é permitir a comunicação e integração entre diferentes aplicações, que podem estar em plataformas, linguagens de programação e sistemas operacionais distintos. Eles fazem isso através de protocolos como HTTP e padrões como SOAP e REST, facilitando a troca de dados e funcionalidades entre sistemas distribuídos.

Pergunta 2

Qual é a função principal do AJAX em web services?

  • a. Armazenamento de dados.
  • b. Criptografia de dados.
  • c. Comunicação assíncrona com o servidor.
  • d. Processamento de imagem.
  • e. Autenticação de usuário.
Resposta: c. ✅

Resolução:

  • O AJAX (Asynchronous JavaScript and XML) permite que uma página web se comunique com o servidor de forma assíncrona, ou seja, sem precisar recarregar toda a página. Isso permite uma experiência mais fluida para o usuário, pois apenas os dados necessários são trocados com o servidor, e a página continua interativa durante essa comunicação.

Pergunta 3

Em que circunstância SOAP é preferível a REST em web services?

  • a. Em sistemas que exigem comunicação de estado.
  • b. Para serviços altamente acoplados.
  • c. Quando a simplicidade é prioritária.
  • d. Em serviços que não requerem segurança.
  • e. Em serviços web de baixa escala.
Resposta: b. ❌

Resolução:

  • O SOAP (Simple Object Access Protocol) é preferível ao REST em algumas circunstâncias, como:
    • Alta complexidade e acoplamento: SOAP é utilizado quando se exige uma comunicação mais robusta e padronizada, frequentemente em sistemas empresariais que requerem transações complexas e segurança avançada.
    • Segurança e confiabilidade: SOAP oferece suporte nativo a padrões como WS-Security, que garante segurança em ambientes corporativos que demandam alta proteção de dados.
    • Comunicação de estado: SOAP pode lidar melhor com serviços que requerem a manutenção do estado (por exemplo, transações bancárias).

Pergunta 4

Para que serve UDDI em web services?

  • a. Criptografia.
  • b. Formatação de texto.
  • c. Autenticação.
  • d. Registro de serviços.
  • e. Banco de dados.
Resposta: d. ✅

Resolução:

  • O UDDI (Universal Description, Discovery, and Integration) é um padrão para o registro e descoberta de web services. Ele atua como uma espécie de "catálogo" ou "páginas amarelas" para serviços, permitindo que os desenvolvedores e sistemas encontrem e utilizem serviços disponíveis na rede.

Pergunta 6

Web services podem ser usados para integrar aplicações escritas em diferentes linguagens de programação.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ✅

Resolução:

  • Os web services são projetados para permitir a comunicação entre aplicações, independentemente da linguagem de programação utilizada. Eles utilizam protocolos padrão, como HTTP, e formatos de dados como XML e JSON, que são independentes de linguagem. Pergunta 7

Qual é a principal vantagem da arquitetura de microsserviços?

  • a. Complexidade aumentada.
  • b. Processamento centralizado.
  • c. Flexibilidade e escalabilidade.
  • d. Dependência de plataforma.
  • e. Alto acoplamento.
Resposta: c. Flexibilidade e escalabilidade. ✅

Resolução:

  • A principal vantagem da arquitetura de microsserviços é a sua capacidade de ser flexível e escalável. Cada microsserviço é responsável por uma função específica e pode ser desenvolvido, implantado e escalado de forma independente. Isso permite:
    • Flexibilidade: Diferentes equipes podem trabalhar em serviços distintos de forma paralela, usando tecnologias diferentes.
    • Escalabilidade: Apenas os serviços que exigem mais recursos precisam ser escalados, economizando recursos e melhorando a eficiência.

Pergunta 9

O protocolo SOAP é incompatível com HTTP.

Escolha uma opção: Verdadeiro ou Falso.

Resposta: Verdadeiro. ❌ Resposta: Falso. ✅

Resolução:

  • O protocolo SOAP (Simple Object Access Protocol) é compatível com HTTP e frequentemente usa o HTTP como protocolo de transporte. Embora o SOAP possa ser transmitido via outros protocolos, como SMTP ou TCP, o HTTP é o mais comum devido à sua ampla aceitação e facilidade de uso na comunicação de web services.
