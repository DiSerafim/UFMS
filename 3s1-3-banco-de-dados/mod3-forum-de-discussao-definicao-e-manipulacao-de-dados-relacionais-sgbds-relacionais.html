Materiais

Neste módulo um dos assuntos que estudamos foram as formas de realizar busca de dados em SGBDs relacionais. Sabemos que todas as tabelas possuem uma estrutura de índices em sua chave primária: esse índice é uma estrutura que o SGBD utiliza para buscar tuplas no banco de dados de forma otimizada. Adicionalmente, podemos configurar índices em atributos que não necessariamente fazem parte da chave primária, mas que também são bastante utilizados durante as consultas.

Conteúdo

Imagine um banco de dados que você projetou, descreva alguma estrutura indexada que você precisou definir, explique a necessidade dela e quais buscas ela poderia otimizar.

SGBDs Relacionais

Banco de dados de uma loja de e-commerce

O banco de dados contém as tabelas (cliente, pedido, produto, estoque).

Estrutura indexada:

  • índice no atributo 'email' da tabela 'cliente'.
                id: (INTEGER, primary key),
                nome: (VARCHAR),
                email: (VARCHAR),
                endereco: (VARCHAR),
                telefone: (VARCHAR),

A importância do Índice:

  • A tabela 'cliente' possui grande quantidade de registros, e uma das operações mais realizadas no sistema é a busca por clientes usando o atributo 'email'. O email é frequentemente usado para login, recuperação de senha, envio de notificações e campanhas de marketing.

Ex.:

                CREATE INDEX id_cliente_email ON cliente (email);

Vantagens deste índice:

  • As consultas podem ser executadas mais rápidas no filtro WHERE já que o índice permite acesso diretos aos registros correspondentes.

Ex.:

                SELECT * FROM cliente WHERE email = 'ex@ex.com';
