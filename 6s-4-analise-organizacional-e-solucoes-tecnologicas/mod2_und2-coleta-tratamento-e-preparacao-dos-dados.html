📊 1. A Importância dos Dados

whatshot Dados são o novo petróleo

Assim como o petróleo impulsionou a era industrial, os dados são o recurso estratégico da era digital. No entanto, dados brutos precisam ser refinados, tratados e preparados para gerar valor real.

error_outline O princípio fundamental: "Garbage In, Garbage Out" (Entra lixo, sai lixo)

Dados mal coletados ou mal tratados geram análises ruins, decisões equivocadas e soluções tecnológicas ineficazes. A qualidade da sua análise é diretamente proporcional à qualidade dos seus dados.

bug_report Exemplos de problemas comuns em dados brutos:

  • 📝 Erros de classificação: Um cliente pode ser classificado como "inativo" quando ainda está ativo, distorcendo métricas de churn.
  • 🔄 Dados duplicados: O mesmo registro aparece múltiplas vezes, inflando contagens e enviesando médias.
  • ❓ Valores ausentes (missing values): Campos vazios que impossibilitam cálculos ou exigem tratamento especial.
  • 📏 Formatos inconsistentes: Datas em diferentes padrões (DD/MM/AAAA vs MM/DD/AAAA) ou números com separadores diferentes.
  • 🎯 Outliers não tratados: Valores extremos que podem distorcer completamente a análise.

psychology Mineração de dados (Data Mining)

A mineração de dados é o processo de descobrir padrões, correlações e insights úteis a partir de grandes volumes de dados. Mas atenção: mineração de dados sem pré-processamento adequado é como garimpar no lixo - você pode até encontrar algo, mas a maioria será descarte.

🛠️ 2. Softwares versus Bibliotecas

Para realizar análise e tratamento de dados, você tem duas abordagens principais: usar softwares com interface gráfica ou bibliotecas de programação. Cada uma tem seus pontos fortes e fracos.

dashboard Softwares Especializados

Exemplos: Orange Lab, Weka, Pentaho, RapidMiner, KNIME

✅ Vantagens:

  • Fácil operação com interface visual (drag-and-drop)
  • Sem necessidade de codificação
  • Ambiente amigável para iniciantes
  • Visualização rápida de resultados
  • Curva de aprendizado mais suave

❌ Desvantagens:

  • Limitação de escopo e funcionalidades
  • Possível licença de uso (versões pagas)
  • Menos flexibilidade para análises customizadas
  • Dificuldade para replicar pipelines complexos
  • Processamento limitado para big data

code Bibliotecas de Programação

Exemplos: Pandas (Python), NumPy (Python), dplyr (R), tidyverse (R)

✅ Vantagens:

  • Máxima flexibilidade e controle sobre a análise
  • Código escalável e reproduzível
  • Robusto para grandes volumes de dados
  • Integração com outras ferramentas (APIs, bancos de dados)
  • Comunidade ativa e vasta documentação
  • Gratuito e open-source

❌ Desvantagens:

  • Requer conhecimento de linguagem de programação
  • Curva de aprendizado mais íngreme
  • Debugging e erros inerentes ao programador
  • Configuração inicial de ambiente

insights Qual escolher?

Para iniciantes ou análises rápidas: Comece com Orange Lab - é gratuito, visual e muito intuitivo. Ótimo para aprender os conceitos sem se preocupar com sintaxe.

Para projetos profissionais ou em escala: Invista em aprender Python com Pandas. É o padrão da indústria para ciência de dados e será um diferencial no seu currículo.

Melhor abordagem: Use os dois! Prototipe no Orange para validar ideias rapidamente e depois implemente em Python para produção.

🔍 5. Identificando os Dados - Tipos e Estrutura

table_chart Tipos de dados (Data Types)

  • 🏷️ Categórico (Nominal): Categorias sem ordem intrínseca. Ex: "Bairro", "Tipo de via", "Situação da pavimentação" (Boa/Regular/Ruim). object/category
  • 📊 Numérico Discreto: Números inteiros contáveis. Ex: "Número de buracos na via", "Quantidade de moradores". int64
  • 📈 Numérico Contínuo: Números reais mensuráveis. Ex: "Extensão da via (km)", "Tempo de alagamento (horas)". float64
  • 🔘 Booleano: Verdadeiro/Falso. Ex: "Tem drenagem? (Sim/Não)". bool
  • 📅 Data/Hora: Datas e timestamps. Ex: "Data da última manutenção". datetime64

📈 6. Análise Exploratória Inicial - Métricas dos Dados

calculate Feature Statistics - Principais métricas:
  • 📊 Média (Mean): Soma dos valores dividida pelo número de observações. Sensível a outliers.
  • 📐 Mediana (Median): Valor central quando os dados estão ordenados. Robusta a outliers.
  • 📏 Desvio-padrão (Std): Medida de dispersão média dos dados em relação à média.
  • 📉 Variância (Variance): Quadrado do desvio-padrão.
  • 📊 Mínimo e Máximo (Min/Max): Limites inferior e superior dos dados.
  • 📋 Quartis (Q1, Q2, Q3): Dividem os dados em 4 partes iguais. Q2 = mediana.
  • 🎯 Intervalo Interquartil (IQR): Q3 - Q1. Útil para detectar outliers.

🧹 7. Pré-processamento: Imputação e Tratamento de Dados

cleaning_services O que é imputação?

Imputação é o processo de substituir valores ausentes (missing values) por valores estimados, permitindo que a análise seja realizada sem perda de observações.

Métodos de Imputação no Orange Lab (Widget "Impute")

  • 📊 Média (Mean): Substitui valores ausentes pela média da coluna. Bom para dados simétricos sem outliers.
  • 📐 Mediana (Median): Substitui pela mediana. Mais robusto para dados com outliers.
  • 🎲 Aleatório (Random): Amostra aleatória dos valores existentes. Preserva distribuição.
  • 📈 Regressão (Model-based): Usa um modelo para prever valores ausentes. Mais sofisticado.
  • 📋 Moda (Most frequent): Para dados categóricos, usa o valor mais comum.
  • ❌ Remover (Remove): Exclui linhas com valores ausentes. Útil quando poucos registros são afetados.

Imputação em Python com Pandas

# Identificando valores ausentes
print(df.isnull().sum())

# Imputação por média (coluna numérica)
df['nota_manutencao'].fillna(df['nota_manutencao'].mean(), inplace=True)

# Imputação por mediana (mais robusto para outliers)
df['extensão_km'].fillna(df['extensão_km'].median(), inplace=True)

# Imputação por moda (para dados categóricos)
df['bairro'].fillna(df['bairro'].mode()[0], inplace=True)

# Imputação com valor específico
df['tem_drenagem'].fillna('Não informado', inplace=True)

# Método avançado: forward fill (propaga o último valor válido)
df.fillna(method='ffill', inplace=True)

# Removendo linhas com qualquer valor ausente (último recurso)
df.dropna(inplace=True)

⚙️ 8. Pré-processamento Avançado

transform Outras técnicas importantes de pré-processamento:

  • 🔧 Normalização/Padronização: Ajustar escalas de variáveis numéricas para que tenham média 0 e desvio 1 (StandardScaler) ou estejam no intervalo [0,1] (MinMaxScaler). Essencial para algoritmos sensíveis à escala (SVM, redes neurais, KNN).
  • 🏷️ Codificação de variáveis categóricas: Converter categorias em números (One-Hot Encoding, Label Encoding) para algoritmos de machine learning.
  • 🔄 Remoção de duplicatas: Identificar e eliminar registros duplicados que podem enviesar a análise.
  • 📊 Detecção e tratamento de outliers: Usar IQR ou Z-score para identificar valores extremos e decidir se removê-los, transformá-los ou tratá-los separadamente.
  • 📅 Extração de características (Feature Engineering): Criar novas variáveis a partir das existentes (ex: dia_da_semana a partir de uma data, ou faixa_etária a partir da idade).
  • 📉 Redução de dimensionalidade: PCA (Principal Component Analysis) para reduzir número de variáveis preservando informação.
# Normalização (StandardScaler - scikit-learn)
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
df_normalizado = scaler.fit_transform(df[['extensao_km', 'ocorrencias']])

# One-Hot Encoding para variáveis categóricas
df = pd.get_dummies(df, columns=['tipo_via', 'situacao_pav'])

# Removendo duplicatas
df.drop_duplicates(inplace=True)

# Detectando outliers com IQR
Q1 = df['ocorrencias'].quantile(0.25)
Q3 = df['ocorrencias'].quantile(0.75)
IQR = Q3 - Q1
limite_superior = Q3 + 1.5 * IQR
outliers = df[df['ocorrencias'] > limite_superior]
print(f"Outliers encontrados: {len(outliers)}")

📊 9. Comparação Final: Antes e Depois do Pré-processamento

report_problem Dataset Bruto

  • ❌ 15% de valores ausentes
  • ❌ 8% de registros duplicados
  • ❌ Escalas inconsistentes (km e metros misturados)
  • ❌ Outliers distorcendo médias
  • ❌ Categorias com textos inconsistentes ("Sim"/"S"/"TRUE")
  • ❌ Datas em formatos diferentes

check_circle Dataset Preparado

  • ✅ 0% valores ausentes (imputação adequada)
  • ✅ Registros únicos e consistentes
  • ✅ Dados padronizados (mesma unidade de medida)
  • ✅ Outliers tratados ou sinalizados
  • ✅ Categorias normalizadas (padronização de texto)
  • ✅ Datas no formato datetime
  • ✅ Pronto para modelagem e análise

auto_awesome Checklist de qualidade de dados (Data Quality)

  • ✔️ Precisão: Os dados representam corretamente a realidade?
  • ✔️ Completude: Todos os valores necessários estão presentes?
  • ✔️ Consistência: Os dados seguem o mesmo padrão em toda a base?
  • ✔️ Validade: Os dados estão no formato esperado e dentro dos limites definidos?
  • ✔️ Unicidade: Não há registros duplicados?
  • ✔️ Atualidade: Os dados são recentes e relevantes para o problema?

🏘️ Aplicação Prática: Preparação dos Dados "Vias da Cabanagem"

apartment Dataset do problema de infraestrutura em Belém/PA

Cenário: Coletamos dados sobre 50 vias do bairro da Cabanagem, mas o dataset apresenta problemas:

  • 10 registros sem informação sobre "pavimentação"
  • 3 registros com extensão da via em metros ao invés de km
  • 5 registros duplicados
  • Valores inconsistentes em "tipo_drenagem" ("Sim", "S", "1", "True")

Pipeline de pré-processamento aplicado:

  1. Padronização de extensão: converter tudo para km (metros/1000)
  2. Imputação de "pavimentação" pela moda (valor mais frequente)
  3. Remoção de duplicatas
  4. Normalização da coluna "tipo_drenagem" (mapeamento "Sim"/"S"/"1"/"True" → "Sim", "Não"/"N"/"0"/"False" → "Não")
  5. Exportação do dataset limpo para análise exploratória
