🎨 1. Prototipação

A prototipação é uma versão preliminar da aplicação que permite validar ideias, testar fluxos e coletar feedback antes do desenvolvimento completo.

style

Tipos de Protótipos

delete_forever Protótipos Descartáveis (Throwaway)

Finalidade: Validar ideias e requisitos rapidamente.

Processo: Cria-se um protótipo rápido, testa-se com usuários, coleta-se feedback e descarta-se o protótipo. O aprendizado é aplicado no desenvolvimento final.

✅ Ideal para: Projetos com requisitos incertos, validação de interface, testes de usabilidade rápidos.

Exemplo: Esboços em papel (paper prototyping) ou wireframes no Balsamiq que serão descartados após validação.

evolution Protótipos Evolutivos (Evolutionary)

Finalidade: Servir como base para o produto final.

Processo: O protótipo inicial é refinado iterativamente até se tornar o produto final.

✅ Ideal para: Projetos ágeis, sistemas complexos onde o aprendizado é contínuo, entregas incrementais.

Exemplo: MVP (Minimum Viable Product) que evolui para versões mais completas, como um dashboard que começa com poucos gráficos e ganha funcionalidades a cada sprint.
thumb_up Benefícios da Prototipação
  • ✅ Feedback rápido: Usuários interagem com algo concreto desde cedo
  • ✅ Redução de riscos: Erros são identificados antes do desenvolvimento
  • ✅ Validação com o usuário: Garante que a solução atende às reais necessidades
  • ✅ Comunicação efetiva: Protótipos visuais facilitam o alinhamento entre equipe e cliente
  • ✅ Economia de tempo e custo: Corrigir um protótipo é muito mais barato que refatorar código

🔌 4. API - Application Programming Interface

api O que é uma API?

API é um conjunto de regras e protocolos que permite a comunicação entre diferentes sistemas de software. É como um "garçom" que leva o pedido do cliente (aplicação) até a cozinha (servidor) e traz a resposta de volta.

🌤️ Exemplo prático - API de Clima

Requisição GET https://api.climatempo.com.br/v1/weather?city=Belem

Resposta da API (formato JSON):

{
  "cidade": "Belém",
  "temperatura": "30°C",
  "chuva": "0%",
  "umidade": "78%",
  "proxima_atualizacao": "2026-06-03T15:00:00Z"
}

O aplicativo de clima solicita dados a essa API, que responde com informações atualizadas. O app então exibe para o usuário.

Tipos de API mais comuns

🔓 API REST (Representational State Transfer)

Baseada em HTTP, utiliza métodos como GET, POST, PUT, DELETE. É a mais utilizada na web moderna.

Exemplo: APIs do Twitter, GitHub, Google Maps.

📦 API GraphQL

Permite que o cliente solicite exatamente os campos que precisa, reduzindo over-fetching e under-fetching.

Exemplo: APIs do Facebook, Shopify, GitHub GraphQL.

⚡ API WebSocket

Conexão bidirecional em tempo real (baixa latência). Útil para chats, notificações, jogos.

Exemplo: WhatsApp Web, sistemas de trading financeiro.

security Boas práticas para APIs (RESTful):
  • Utilizar HTTP methods adequados (GET para leitura, POST para criação, PUT para atualização, DELETE para remoção)
  • Retornar códigos de status HTTP significativos (200 OK, 201 Created, 400 Bad Request, 401 Unauthorized, 404 Not Found, 500 Internal Server Error)
  • Documentar a API com Swagger/OpenAPI
  • Versionar a API (ex: /v1/, /v2/)
  • Autenticar e autorizar requisições (API Keys, JWT, OAuth2)

🔗 5. Integração da Solução

Integração refere-se à conexão entre diferentes partes de um sistema: front-end, back-end, banco de dados, APIs externas. Uma boa integração garante uma experiência fluida e eficiente.

Os três pilares da integração

1
Front-end
Interface visual (HTML/CSS/JS)
Interação com usuário
2
Back-end
Lógica de negócio (Node.js/Java/Python)
Processamento e regras
3
Banco de Dados
Armazenamento persistente
Consultas e transações

Front-end (parte visual)

web Tecnologias e responsabilidades:
  • Tecnologias: HTML, CSS, JavaScript, TypeScript, React, Vue.js, Angular
  • Função: Interface com o usuário (botões, menus, telas, formulários, mapas)
  • O que faz: Envia dados para o back-end via API, recebe respostas e atualiza a interface dinamicamente
  • Foco: Experiência do usuário (UX/UI), acessibilidade, responsividade

Back-end (lógica por trás)

storage Tecnologias e responsabilidades:
  • Tecnologias: Node.js, Python (Django/Flask), Java (Spring Boot), PHP (Laravel), C# (.NET), Go, Ruby on Rails
  • Função: Processar requisições, aplicar regras de negócio, autenticar usuários, gerenciar sessões
  • O que faz: Conecta front-end ao banco de dados, integra APIs externas, garante segurança e performance
  • Foco: Lógica de negócio, integridade dos dados, eficiência

Banco de Dados

database Tipos e responsabilidades:
  • Relacional (SQL): PostgreSQL, MySQL, Oracle, SQL Server → dados estruturados, consistência ACID, relacionamentos
  • Não Relacional (NoSQL): MongoDB (documentos), Redis (cache/chave-valor), Cassandra (colunas) → flexibilidade, escalabilidade horizontal
  • Função: Armazenar dados permanentemente, permitir consultas eficientes, garantir integridade referencial
  • O que faz: CRUD (Create, Read, Update, Delete), transações, backups, otimização de consultas

🏘️ Aplicação Prática: Integração no Projeto "Vias da Cabanagem"

apartment Como integrar o dashboard de monitoramento de vias

// Exemplo de integração Front-end (React) com Back-end (Node.js)

// Front-end (React) - Buscando dados de uma via específica
async function buscarVia(id) {
  const resposta = await fetch(`https://api.viasdacabanagem.com.br/v1/vias/${id}`, {
    headers: { 'Authorization': `Bearer ${token}` }
  });
  const dados = await resposta.json();
  console.log(dados); // { nome: "Av. Siqueira Mendes", pavimentacao: "Parcial", ... }
}

// Back-end (Node.js + Express) - Endpoint que retorna dados do banco
app.get('/api/v1/vias/:id', autenticar, async (req, res) => {
  const via = await ViaModel.findById(req.params.id);
  res.json(via);
});

Resumo da integração proposta para o projeto:

  • 📱 Front-end: React + Leaflet (mapas interativos) + Axios (requisições HTTP)
  • ⚙️ Back-end: Node.js + Express + JWT (autenticação) + bcrypt (senhas)
  • 🗄️ Banco de Dados: PostgreSQL (dados estruturados de vias) + MongoDB (reportes colaborativos não estruturados)
  • 🔌 APIs externas: Leaflet/OpenStreetMap (mapas), API do SINISA (dados públicos de saneamento)
  • 🔐 Segurança: HTTPS, validação de entrada, rate limiting, sanitização de dados

Essa arquitetura garante escalabilidade (podemos adicionar novas vias e novos bairros facilmente), segurança (dados de localização são sensíveis) e experiência fluida para o usuário.

✍️ 7. Mão na Massa - Exercício Prático

edit_note Desafio: Prototipe e integre sua solução

Com base no seu projeto (ou em um projeto hipotético), realize as seguintes atividades:

  1. Prototipação: Crie um wireframe de baixa fidelidade (pode ser papel ou Balsamiq) para a tela principal do seu sistema. Identifique os principais elementos de interface.
  2. Modelagem: Desenhe um diagrama de classes UML simplificado mostrando as principais entidades (ex: Usuário, Via, Reporte).
  3. API: Escreva um exemplo de requisição GET para buscar dados de uma entidade. Qual seria a URL? Qual o formato da resposta?
  4. Integração: Liste as tecnologias que usaria para Front-end, Back-end e Banco de Dados. Justifique cada escolha.

Desafio extra: Pesquise sobre CI/CD (Integração Contínua/Entrega Contínua) – como isso se relaciona com a integração de soluções?
