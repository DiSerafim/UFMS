📌 Sobre a Atividade do Módulo 3

Neste módulo, você deverá desenvolver um projeto que integre modelagem e manipulação de banco de dados com o uso de controle de versão para gerenciamento do código.

🎯 Requisitos do projeto:

  • ✅ Modelagem e manipulação de banco de dados
    • Criar um modelo de dados para um sistema, definindo entidades, relacionamentos e restrições
    • Implementar o esquema do banco de dados utilizando SQL
    • Executar operações de manipulação de dados (inserção, atualização, remoção e consultas)
  • ✅ Uso de controle de versão
    • Utilizar um sistema de controle de versão (como Git) para gerenciar a evolução do projeto
    • Criar e organizar um repositório no GitHub, utilizando boas práticas de versionamento
    • Registrar commits frequentes, incluindo mensagens explicativas sobre as alterações realizadas
  • Após concluir a implementação, publique o código em um repositório no GitHub e forneça o link no relatório

🗄️ Modelagem do Banco de Dados (MongoDB + Mongoose)

📊 Modelo de dados desenvolvido para a Cidade Virtual: 
// Modelo de Usuário (User.js)
const userSchema = new mongoose.Schema({
  nome: { type: String, required: true },
  email: { type: String, required: true, unique: true },
  senha: { type: String, required: true },
  tipoPerfil: { 
    type: String, 
    enum: ['morador', 'comerciante', 'autonomo', 'lider'],
    required: true 
  },
  telefone: String,
  cep: String,
  dataCadastro: { type: Date, default: Date.now }
});

// Modelo de Comércio (Comercio.js)
const comercioSchema = new mongoose.Schema({
  usuarioId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  nomeFantasia: { type: String, required: true },
  descricao: String,
  categoria: { 
    type: String, 
    enum: ['alimentacao', 'reparos', 'beleza', 'saude', 'educacao', 'outros'],
    required: true 
  },
  endereco: { type: String, required: true },
  lat: Number,
  lng: Number,
  whatsapp: String,
  fotoPerfil: String,
  dataCadastro: { type: Date, default: Date.now }
});

// Modelo de Evento (Evento.js)
const eventoSchema = new mongoose.Schema({
  titulo: { type: String, required: true },
  descricao: String,
  dataHora: { type: Date, required: true },
  local: String,
  tipo: { type: String, enum: ['mutirao', 'doacao', 'feira', 'oficina'] },
  criadoPorUsuarioId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true }
});
🔗 Relacionamentos (referências entre coleções):
  • Comercio.usuarioId → referência ao User que criou o comércio
  • Evento.criadoPorUsuarioId → referência ao User que criou o evento
  • Avaliacao.comercioId → referência ao Comercio avaliado
  • Avaliacao.usuarioId → referência ao User que fez a avaliação
💡 Decisão de modelagem: Optei por MongoDB (NoSQL) ao invés de SQL relacional devido à flexibilidade de esquema e facilidade de integração com a stack MERN. As referências são feitas manualmente via ObjectId (populate do Mongoose), simulando relacionamentos.

📜 Operações de manipulação de dados (CRUD)

Foram implementadas as operações básicas de manipulação de dados conforme os requisitos do módulo:

➕ Create (Inserção)

Exemplo: Cadastro de novo comércio via POST /api/comercios

db.comercios.insert({
  nomeFantasia: "Padaria do João",
  categoria: "alimentacao",
  endereco: "Rua das Flores, 123"
})

📖 Read (Consulta)

Exemplo: Buscar comércios por categoria

db.comercios.find({ 
  categoria: "alimentacao" 
})

✏️ Update (Atualização)

Exemplo: Alterar horário de funcionamento

db.comercios.update(
  { _id: ObjectId("...") },
  { $set: { whatsapp: "(91) 99999-8888" } }
)

🗑️ Delete (Remoção)

Exemplo: Remover um evento cancelado

db.eventos.deleteOne({ 
  _id: ObjectId("...") 
})
📡 Consultas avançadas implementadas na API:
  • Busca por categoria + nome (regex case-insensitive)
  • Filtro por proximidade (calculado via coordenadas, com sort)
  • Consulta com populate para retornar dados do usuário autor do evento
  • Agregação: contagem de comércios por categoria para o dashboard

📦 Controle de Versão: Estrutura e boas práticas

🌿 Estrutura de branches adotada no Módulo 3: 
main (produção)
  └── develop (integração)
       ├── feature/modelagem-banco
       ├── feature/controllers-crud
       ├── feature/rotas-api
       ├── feature/consultas-avancadas
       └── feature/documentacao-swagger
📝 Exemplos de commits semânticos (Conventional Commits): 
feat: adiciona modelo Mongoose de Comercio
feat: implementa CRUD completo de Eventos
fix: corrige validação de email no cadastro de usuário
docs: atualiza README com instruções do banco de dados
test: adiciona testes unitários para o controller de comércios
chore: configura variáveis de ambiente para MongoDB Atlas
refactor: simplifica lógica de busca por categoria
🔄 Fluxo de trabalho adotado:
  1. Criação de branch a partir de develop: git checkout -b feature/nova-funcionalidade
  2. Commits atômicos e frequentes com mensagens no padrão Conventional Commits
  3. Sincronização diária: git pull --rebase origin develop
  4. Abertura de Pull Request no GitHub para revisão do código
  5. Merge na develop após aprovação (geralmente com squash)
  6. Periodicamente, merge da develop na main para gerar uma nova versão estável
🔍 Diferencial implementado: Adicionei um hook de pré-commit usando Husky + lint-staged para rodar ESLint e Prettier automaticamente antes de cada commit, garantindo padronização do código.
