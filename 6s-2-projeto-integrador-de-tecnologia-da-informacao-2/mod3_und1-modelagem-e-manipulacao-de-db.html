🗄️ O que é um banco de dados?

Um banco de dados é um sistema para armazenar, organizar e recuperar informações de maneira estruturada. Ele permite que sistemas armazenem e gerenciem grandes volumes de dados com segurança, eficiência e consistência.

❌ Sem banco de dados

  • Dados em arquivos de texto ou planilhas
  • Sem concorrência (dois usuários corrompem o arquivo)
  • Sem segurança de acesso granular
  • Sem backup automático ou recuperação
  • Exemplo: salvar lista de comércios em um arquivo .txt

✅ Com banco de dados

  • Dados centralizados, consistentes e seguros
  • Suporte a múltiplos acessos concorrentes
  • Controle de usuários e permissões
  • Backup, replicação e recuperação de falhas
  • Exemplo: MongoDB com os comércios da Cidade Virtual
💡 Analogia: Um banco de dados é como uma biblioteca organizada. Os livros (dados) têm catalogação, índices, áreas de leitura e regras de empréstimo. Sem a organização, seria impossível encontrar um livro específico entre milhares.

📊 Tipos de banco de dados: Relacional vs NoSQL

📐 Relacional (SQL)

Exemplos: MySQL, PostgreSQL, SQLite, Oracle, SQL Server

Características:

  • Dados organizados em tabelas (linhas e colunas)
  • Relacionamentos via chaves estrangeiras (1:N, N:N)
  • Esquema fixo (define-se colunas antes de inserir dados)
  • Linguagem SQL (padrão)
  • Garantia ACID (Atomicidade, Consistência, Isolamento, Durabilidade)

🍃 NoSQL (Não Relacional)

Exemplos: MongoDB, Firebase, Cassandra, Redis

Características:

  • Dados em documentos (JSON/BSON), grafos, chave-valor ou colunas
  • Esquema flexível (campos podem variar entre documentos)
  • Escalabilidade horizontal fácil (sharding)
  • Alta performance para grandes volumes
  • Modelagem orientada ao que a aplicação precisa
🚀 Por que escolhemos MongoDB para a Cidade Virtual? O MongoDB (NoSQL) oferece flexibilidade de esquema, ideal para um projeto em evolução. Um comércio pode ter telefone, outro pode ter WhatsApp e site. Não precisamos de colunas fixas como no SQL. Além disso, a integração com Node.js/React é natural (JSON em todas as camadas).

📐 Modelagem de dados: do mundo real ao banco

Modelagem de dados é o processo de criar uma representação conceitual dos dados que serão armazenados, seus atributos e seus relacionamentos. É uma etapa crucial antes de qualquer implementação.

Etapas da modelagem:
  • Modelagem conceitual (alto nível): Identificar entidades (ex: Comercio, Usuario, Evento) e seus relacionamentos (ex: Usuario cadastra Comercio). Ferramenta: Diagrama Entidade-Relacionamento (DER) conceitual.
  • Modelagem lógica (independente de tecnologia): Definir atributos de cada entidade (ex: Comercio tem nome, descrição, categoria, endereço). Definir chaves primárias e estrangeiras.
  • Modelagem física (dependente do SGBD): Traduzir o modelo lógico para o banco específico (ex: coleções e documentos no MongoDB, ou tabelas e índices no MySQL).
🎯 Exemplo: Modelagem da Cidade Virtual (MongoDB - Mongoose) 
// Modelo de Usuário (Mongoose Schema)
const UsuarioSchema = new mongoose.Schema({
    nome: { type: String, required: true },
    email: { type: String, required: true, unique: true },
    senhaHash: { type: String, required: true },
    tipoPerfil: { type: String, enum: ['morador', 'comerciante', 'autonomo', 'lider'] },
    telefone: String,
    dataCadastro: { type: Date, default: Date.now }
});

// Modelo de Comércio
const ComercioSchema = new mongoose.Schema({
    nomeFantasia: { type: String, required: true },
    descricao: String,
    categoria: String,
    endereco: String,
    whatsapp: String,
    criadoPor: { type: mongoose.Schema.Types.ObjectId, ref: 'Usuario' } // Relacionamento 1:N
});

🔗 Relacionamentos entre dados (1:N, N:N)

Os dados raramente existem isoladamente. Relacionamentos definem como entidades se conectam. Os principais tipos são:

1:1 (um para um)

Exemplo: Um usuário tem um único perfil de endereço principal. No MongoDB, podemos incorporar o documento ou referenciar por ID.

1:N (um para muitos)

Exemplo: Um comerciante (usuário) cadastra vários comércios. No MongoDB, usamos referência (ObjectId) na coleção Comercio apontando para Usuario.

N:N (muitos para muitos)

Exemplo: Um evento pode ter muitos participantes (usuários), e um usuário pode participar de muitos eventos. Solução: array de ObjectIds (participantes: [id1, id2]).

💡 Decisão de modelagem: No MongoDB, você pode incorporar (embed) documentos filhos dentro do pai (boa para leitura, ruim para atualizações) ou referenciar (reference) via ObjectId (mais flexível, mas exige joins manuais – duas consultas). Para a Cidade Virtual, usamos referência (populate do Mongoose) na maioria dos casos.

🔌 Integração banco de dados + aplicação (Node.js + MongoDB)

No projeto Cidade Virtual (stack MERN), a integração entre o banco de dados (MongoDB) e a aplicação (Node.js/Express) é feita através do ODM Mongoose. Mongoose fornece uma camada de abstração para validar dados, converter tipos, criar queries e gerenciar relacionamentos.

Fluxo completo de uma operação de leitura (GET /api/comercios):
  1. Front-end (React): fetch('http://localhost:5000/api/comercios')
  2. Back-end (Express): Roteador recebe a requisição, chama o controller.
  3. Controller: await Comercio.find() - Mongoose consulta o MongoDB.
  4. MongoDB: Retorna documentos da coleção "comercios".
  5. Controller: Envia a lista em JSON para o front-end.
  6. Front-end (React): Atualiza o estado com os dados, renderiza os cards.
// Exemplo: Controller de listagem de comércios (Node.js + Mongoose)
async function listarComercios(req, res) {
    try {
        const comercios = await Comercio.find()
            .populate('criadoPor', 'nome email') // JOIN com usuário
            .limit(20);
        res.json(comercios);
    } catch (error) {
        res.status(500).json({ mensagem: 'Erro ao buscar comércios', error });
    }
}
📡 Conexão com a aplicação: No arquivo `server.js`, usamos mongoose.connect(process.env.MONGO_URI) para conectar ao MongoDB Atlas. O servidor Express só inicia se a conexão for bem-sucedida.

✏️ Manipulação de dados: CRUD no MongoDB com Mongoose

As quatro operações fundamentais (Create, Read, Update, Delete) são implementadas no back-end e expostas via API REST para o front-end consumir.

➕ Create (Inserir)

const novo = new Comercio(req.body); await novo.save(); → Insere um novo documento na coleção.

📖 Read (Consultar)

await Comercio.find({ categoria: 'alimentacao' }); → Busca documentos com filtro.

✏️ Update (Atualizar)

await Comercio.findByIdAndUpdate(id, req.body, { new: true }); → Atualiza e retorna o documento atualizado.

🗑️ Delete (Remover)

await Comercio.findByIdAndDelete(id); → Remove o documento da coleção.

Exemplo de rota para criar um novo comércio (com validação de autenticação): 
// routes/comercios.js
router.post('/', autenticarUsuario, async (req, res) => {
    try {
        const { nomeFantasia, descricao, categoria, endereco, whatsapp } = req.body;
        // req.usuarioId vem do middleware de autenticação
        const novoComercio = new Comercio({
            nomeFantasia, descricao, categoria, endereco, whatsapp,
            criadoPor: req.usuarioId
        });
        await novoComercio.save();
        res.status(201).json(novoComercio);
    } catch (error) {
        res.status(400).json({ mensagem: 'Erro ao criar comércio', error });
    }
});

⚡ Índices e performance: buscando dados de forma eficiente

À medida que a quantidade de dados cresce, consultas sem índices ficam lentas. Um índice é uma estrutura de dados que acelera as operações de busca (semelhante ao índice de um livro).

Exemplo de criação de índice no MongoDB (via Mongoose): 
// No schema do Comercio
const ComercioSchema = new mongoose.Schema({ ... });
ComercioSchema.index({ categoria: 'text' }); // Índice textual para busca
ComercioSchema.index({ criadoPor: 1 });        // Índice para relacionamento
🚀 Na prática (Cidade Virtual): Criamos índices nos campos mais usados em filtros: categoria (busca por categoria), criadoPor (listar comércios de um usuário), dataCadastro (ordenar por recentes). Isso reduz o tempo de resposta de segundos para milissegundos.

🔒 Segurança e boas práticas no acesso ao banco de dados

  • Validação de entrada: Sempre valide dados no back-end (Mongoose já faz validação básica; podemos usar Joi ou express-validator).
  • Injeção de SQL/NoSQL: No MongoDB, evite concatenar diretamente entradas do usuário em queries. Use os operadores do Mongoose (ex: Comercio.find({ nome: req.query.nome }) é seguro).
  • Princípio do menor privilégio: Crie um usuário do MongoDB específico para a aplicação, com permissões apenas de leitura/escrita no banco da Cidade Virtual (não com permissões administrativas).
  • Variáveis de ambiente: A string de conexão (URI do MongoDB) deve estar no arquivo .env, nunca versionada no GitHub.
  • Backup automático: O MongoDB Atlas oferece snapshots automáticos diários. Para desenvolvimento local, exporte periodicamente com mongodump.
⚠️ Atenção: Nunca exponha a string de conexão do banco em código público. No repositório da Cidade Virtual, usamos .env.example com variáveis fictícias, e o .gitignore bloqueia o .env real.

🏙️ Exemplo prático: Modelagem completa da Cidade Virtual (MERN)

Diagrama de entidades (no MongoDB, "coleções") implementadas:
  • usuarios – _id, nome, email, senhaHash, tipoPerfil, telefone, dataCadastro
  • comercios – _id, nomeFantasia, descricao, categoria, endereco, whatsapp, foto, criadoPor (ref: usuarios), dataCriacao
  • eventos – _id, titulo, descricao, dataHora, local, tipo (mutirao/doacao/feira), criadoPor (ref: usuarios), participantes (array de ref: usuarios)
  • avaliacoes – _id, comercioId (ref: comercios), usuarioId (ref: usuarios), nota (1-5), comentario, data
Relacionamentos implementados:
  • 1:N – Um usuário (comerciante) pode criar vários comércios (campo criadoPor).
  • 1:N – Um comércio pode receber várias avaliações (avaliacoes coleção com comercioId).
  • N:N – Um evento pode ter vários participantes (participantes é um array de ObjectIds de usuários).
📌 Consulta complexa no back-end (exemplo com Mongoose): Buscar comércios de uma categoria, populando o criador e as 5 últimas avaliações. 
const comercios = await Comercio.find({ categoria: req.query.categoria })
    .populate('criadoPor', 'nome email')
    .populate({
        path: 'avaliacoes',
        options: { limit: 5, sort: { data: -1 } }
    });
🎓 Aprendizado principal: A modelagem de dados não é um processo único. Começamos com um DER conceitual, evoluímos para o modelo lógico (identificando atributos e relacionamentos) e, durante a implementação, ajustamos devido a novas demandas (ex: adicionar campo "foto" em Comercios). Essa iteração é natural e saudável!
